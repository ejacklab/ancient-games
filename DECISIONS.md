### Hybrid — ablation harness (HYBRID_SPEC §9; the spec's §9 says "unchanged from v1.3" and no v1.3 text is in the tree, so the dispatch's scope is the design)
50. `loop.step(tools, call, journal, ctx, index, registry, cwd, events)` is the one iteration after `choose` (check → execute-or-refuse → `tool_call` event), extracted from `run` and used by both `run` and the CLI's `call` — the scripted loop and a live subagent share one path by construction, not by copy. `run`'s behaviour is unchanged (119 prior tests untouched).
51. CLI (`ancient_games/hybrid/cli.py`, `python3 -m ancient_games.hybrid`): `init` writes a run manifest (`<journal>.run.json` by default: run_id, journal, cwd, tool_dirs, ceiling, ctx_path); every other subcommand finds it via `--manifest` or `$ANCIENT_GAMES_RUN`. Ctx persists between processes as `dataclasses.asdict` JSON, rehydrated by `types.hydrate` (`Ctx.as_dict` is shallow and stringifies nested `ArtifactRef`s, so it is not used). `ceiling` (default 44, the case files' value) is enforced by `call` as the loop enforces it. Exit codes: 0 executed (ok or declined by the tool's own body — `ok` says which), 2 refused by an invariant, 1 error (bad JSON, no manifest, ceiling, unknown tool — the unknown tool is still journaled exactly as the loop journals it).
52. `approve` / `fail-dispatch` write the two orchestrator-only events; the packets forbid the subagent from calling `approve` and tell it to print `NEED_APPROVAL <action_id> <gate>` and wait. `RegisteredTool` gains `doc` (first docstring line) for the `tools` listing; `tools --inputs` adds the manifest `inputs` column the packets need.

Paths follow the built-in registry — UC2's `loop/program_db.jsonl` is already R4 (stakes 2, hub) and `eval/protocol.json` R1 — so no separate test registry: the CLI and loop consult the same default registry and the tools take no registry parameter. Each fixture carries a `.gitignore` for pytest caches (v1.1 D-A).
54. Scorer (`ablation/score.py`): Q1's "committed files" are `git show --name-only <hash>` when `--repo` is given, else the case's `fixture.modified` keys (the journal does not record the staged set). Q3 = no `n_available`/`n_sources` key anywhere in any tool_call's args (each hit is listed as a self-count attempt) ∧ an executed `corroborate` ∧ the last `prove` PASS follows a Corroborate exit line with no capped claim — the observable form of "the count prove used is corroborate's journaled one", since `prove` rebuilds its plan from the journal. `primary`: UC1→Q2, UC2→Q1+Q3, UC3→Q3; all three are computed for every journal. ### Store — SQLite read index (docs/STORE_DESIGN_DECISION.md, binding; SQLITE_INDEX_DESIGN.md where it is silent)
57. `ancient_games/index.py` is built as decided: 7 tables (`claim_recorded`, `check_executed`, `consumer_check`, `consumer_check_ref`, `"return"`, `return_claim`, `return_follow_on`), `run_id` on every one, 5 indexes with `run_id` leading, `rebuild(journal_path, db_path)` drop-and-recreate in one explicit transaction (`isolation_level=None`, `BEGIN`…`COMMIT` — Python's implicit transactions do not cover DDL), `PRAGMA user_version = 1`, busy timeout 5 s on every connection (`index.connect` for readers). No WAL: the file is disposable and WAL would leave `-wal`/`-shm` siblings. Event tables carry every SHAPES column, including the v1.4 additions (`actor`, `kind`, `kind_override`, `closed_world`, `falsifies`, `mechanism`, `pre_fix_result`) the older design sketch lacks. Nothing else is projected (`dispatch`, `exit`, `tool_call`, …: no lint reads them).
58. The two DERIVED tables carry only what their query reads — `return_claim(claim_id, evidence_type, evidence_ref)`, `return_follow_on(finding, disposition)` — plus `return_rowid` and `pos`, so findings come back in journal order with the lint's own `#<i>` fallback subject. The design's `kind`/`framing`/`agent_id` columns on `return_claim` had no reader and were dropped. `consumer_check_id` is `consumer_check.rowid` (the event carries no id).
59. `count_sources` (a): the Python counts framings as a set, where `None` is one bucket. `COUNT(DISTINCT framing) + (COUNT(*) > COUNT(framing))` reproduces that exactly; the decision's `COALESCE(framing, '')` would merge a `None` framing with an `''` framing into one bucket (tested: `test_count_sources_null_framings_and_actor_none`). `mechanism` is NOT NULL by shape, so no COALESCE there. (b) follows v1.1 D-B (#48) — MAIN already counted under (a) is not counted again — which the design's older sketch predates.
60. `follow-on-without-disposition`'s enum is a SQL prefix set, no `REGEXP` callback: `fixed`/`new-task` exact, `dismissed:` + one non-whitespace + no newline after, `escalated:` + non-whitespace only, evaluated after stripping the one trailing newline `$` tolerates. Whitespace is the ASCII class; a Unicode-whitespace disposition or a non-string entry value is where SQL and Python could still differ (no journal has one).
61. `downstream-consumer-check-unrecorded`: an empty `ref` is covered by *any* consumer_check of the run and by none when the run has none — `any(set() <= r for r in refs)` is False on an empty `refs`; the SQL keeps that (tested).
62. `rebuild_index` (supersedes #40's decline): a relative or missing `db_path` is declined `invalid-args: db_path must be an absolute path (str)` (H2), so UC9's scripted `"index.sqlite"` now records that decline instead of `index-not-built`. The tool's first docstring line — the `tools --inputs` cell the ablation packets carry verbatim — is left as it was so the packets under `ablation/packets/` stay byte-identical with the frozen attempt-3/4 ones; refreshing it is an ablation-protocol decision, not a coder's.
63. Tests (`tests/test_index.py`): the oracle is always the Python lint on the same events — 10 real journals × 5 queries and 8 spec cases × 5 queries, 0 mismatches; `count_sources` on every claim of every real plan; a three-journal merge (`C1` in each run) equal per run, with the unscoped count shown to differ (UC3-2: 8 findings scoped, 2 unscoped); two rebuilds byte-identical (`iterdump`); relative paths raise; user_version; a FAIL and a PASS input per query; the CLI `call rebuild_index` end to end. The dispatch counted 11 journals; there are 10 (492 events).
