### Round 1

**R1.1** Segment independence-trigger: the acceptance cannot be observed by this workflow, and max_attempts=1 puts the required check at risk. The acceptance is row-level: a row either verifier rejects becomes 'not established' and is not retried. The runner in /home/smoke01/dev/ancient-games/.claude/workflows/enhance-ancient-games.js gives one boolean per segment. At :272 a segment is 'verified' only when every verifier passes. At :307-308 a dependent whose dependency is not 'verified' is 'blocked'. At :224-225 dependents receive the worker's whole `findings` and `claims`, not the verifier verdicts. Verifiers are told 'If you are unsure, it does not pass', so one rejected citation makes the segment unverified. With max_attempts=1, independence-check is then blocked and the check the goal requires is never designed. If verifiers instead pass the segment while listing rejected rows, those rows reach independence-check unmarked. That contradicts its inputs_from_deps ('only the rows both verifiers confirmed'). Fix: state acceptance at segment level, so that an attempt passes only when every row in the returned table is confirmed. Set max_attempts=2 so that attempt 2 moves rejected rows to `not_established`; that is feedback a second attempt would actually use. Also, the script's second verifier uses the 'contract' framing (:143-146). It is not a second citation re-opener, so 'two verifiers ... each re-open every citation' does not describe what will run.

**Goal.** Design the check that forbids worker-to-worker sharing or handoff wherever claims must be independent sources. Text only; change no file. Use the verified field names from decision-record and the verified trigger from independence-trigger. RULE, as reachability over the union of all channel types. For each claim c, the group S(c) is the set of segments that declare c as an independent-source claim; only groups with two or more members are checked, and only where the trigger holds. Build one directed graph G whose nodes are worker segment ids (MAIN is not a node) and whose edges are: (e1) shared_state writer -> reader for every key, writer != reader; (e2) shared_state writer <-> writer, both directions, for every pair of distinct writers of one key; (e3) handoff from -> to; (e4) depends_on dependency -> dependent; (e5) control kept by a worker: u -> v when the control holder after u's call is worker v. The only exemption is flow out of a member into a segment outside the group that does not lead on to another member (for example an integration segment whose depends_on lists X and Y, which MAIN mediates). Common input is deliberately permitted and is not a limitation: a key written by MAIN or by a non-member and read by several members, or several members depending on one non-member, creates no member-to-member path; SPEC.md:177 forbids reading a sibling's file, not sharing a brief, and correlated blind spots are FRAMING's job (schema.py:115-116). **Rationale.** Structure: this is the one real dependency in the plan.
