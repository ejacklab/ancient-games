## Standard: the fixed checklist

Answer each item yes or no, with quoted evidence:

1. Every step 1–12 of DESIGN is implemented as written. In particular:
   - the `-z` listings;
   - **one** `git cat-file --batch` call for all blobs in check mode;
   - code-point sort;
   - CRLF→LF;
   - the exact render bytes;
   - temp file then rename in write mode;
   - no write in check mode;
   - the size line printed on every run.
2. Each of DESIGN's six "Must not" holds.
3. Standard library only, and it runs on a fresh clone with only Python 3 and git.
4. Every error reads `<file>: <problem>`, and no input path ends in an uncaught exception.
5. The hooks match DESIGN step 10: the path filter, `--check`, the exit code, and `pre-merge-commit` as a one-line
   `exec`.
6. The unit tests isolate git config and do not touch the real repository.
7. Names and style match the house style. A name that does two jobs is a finding.

A finding is **in criteria** when it breaks a DESIGN step, a "Must not" or a criterion id. Anything else (taste,
improvements, behaviour the spec does not state) is **outside criteria**.
