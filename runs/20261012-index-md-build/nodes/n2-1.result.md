## Choices not in the spec

1. **"not known to git" is a content-class problem.** B1.2 says an untracked entry is an error; B2.5 says a problem in an inactive entry is only a warning. The frozen tests need both (an untracked *active* entry fails, an untracked *retired* one only warns), so the untracked complaint joins the kind/Why/claim problems: error when active, warning when inactive. The failure B1.2 protects against — an untracked entry getting a line — cannot happen for an inactive entry, which gets no line.
2. **The brief's citation line is stale.** The agy row "24,000 bytes per rule file" is `docs/memory-system/CACHES.md:446`; line 519 is the rebuild-cost section. The comment cites 446.
3. **Write mode uses two `git ls-files` calls** (`--cached`, then `--others --exclude-standard`) rather than step 1's single combined call, because the untracked set has to be told apart from the tracked one. Same paths, same order.
4. **"nothing to index" triggers on a missing `project-memory/entries/`**, which subsumes the brief's "no `project-memory/` folder" and also covers a bare `project-memory/` with no entries folder.
5. **A tracked entry deleted from the working tree (deletion not staged) is a warning**, not an error: it keeps its line, and B2.5's reason (one old entry must not block every memory commit) applies.
6. **Snapshot listings cover all of `project-memory/`**, not only `entries/`, so the one `git cat-file --batch` can read the index blob too. That is what keeps the call count at one.
7. **Problems go to stderr, status to stdout**, with stdout flushed first, so a piped hook or CI run reads in order. The spec only says "print".
8. **stdout and stderr are reconfigured to UTF-8** (`errors="replace"`), so a non-ASCII file name cannot raise under `LC_ALL=C`. INDEX.md bytes are encoded explicitly and never go through the locale.
9. **`--check <rev>` with a rev that is not a commit** prints "nothing to check" and exits 0 — the spec's unborn-`HEAD` case generalised to any unresolvable rev.
10. **A blob missing from the snapshot** is reported as `<file>: blob is missing from the snapshot` rather than crashing.
11. **`git config core.hooksPath .githooks` was not run** (design step 17: not without EJ's go); the switch is documented in the hook header.
