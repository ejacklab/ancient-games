# 孫子 (Sun Tzu) — five decisions to finish the source-of-truth memory design

## Answer

**D1 — `project-memory/limits.json`, JSON, one row per agent: `agent`, `version`, `basis`, `source`, `date`, `limits` (each a `value` and a `unit`), and `files` for a combined start load.** JSON is the only standard data format the standard library parses at the repository's declared floor of Python 3.10 (`pyproject.toml:5`; `tomllib` is 3.11+, YAML needs PyYAML), and the row's `basis` carries the note a YAML comment would carry.

**D2 — Row by row, decided by `basis`.** A row with `basis: measured` or `documented` binds by its limits; a row with `basis: example` holds 200 lines and 24,000 bytes; a missing file applies that example to `INDEX.md` and says so; a malformed file fails naming the row; an agent with no row is not a declared reader, so the report prints the declared set and the reviewer checks it.

**D3 — Keep both new paths, keep the old path removed, keep both `changed:` lines, and report the clash in `state.md` for the project owner.** W6.3a's body keeps "every `covers` path either side wrote" and its `fails_if` fails only a missing addition, so keeping both cannot fail the text as written; the repository's current contents must not choose between them.

**D4 — (a), a small standard-library scan inside `tools/memory_index.py`.** Fixed-prefix formats only (AWS access key IDs, private-key blocks, GitHub, GitLab, Slack, Anthropic, OpenAI, Stripe, Google API keys), a `secret-scan:allow` waiver, no entropy and no generic-api-key rule; `check: secret scanner; reviewer` stays, and the reviewer remains the check for passwords, no-prefix tokens and personal data.

**D5 — Now, agy only, one sentinel run with a control.** agy 1.4.0 is installed here (`agy --version`, ran), the design's byte example is agy's documented 24,000 (`tools/memory_index.py:33-36`), and the conflicting 12,000-character figure is reported and lower; one valid run settles the number the design already uses, while measuring every engine now is a campaign with no use case.

## How I decided

1. **D1, place — the record sits with the reader set it describes.** The tool's folder is fixed (`MEMORY_DIR = "project-memory"`, `tools/memory_index.py:38`; `INDEX_PATH` at line 40), so the file that bounds `INDEX.md` sits beside it: `project-memory/limits.json`. My #9 — 「故善戰者，致人而不致於人。」 (quoted) — the tool comes to one record; it does not hold copies in its constants, in B4.1 and in Rd3.1b and keep them in step by hand. This also follows last round's 3-of-6 reading that the record is the project's own, not the kit's.

2. **D1, format — the floor and the standard library decide it.** `json` is standard library (research, verified); YAML needs PyYAML (research, verified), and the fact that `import yaml` happens to succeed on this machine is not portability; `tomllib` is standard library only from 3.11 (research, verified), and this repository declares `requires-python = ">=3.10"` (`pyproject.toml:5`). TOML is the attractive middle — comments, obvious semantics — but it would raise the kit's floor to 3.11 or need a fallback parser, and nothing in this run authorises that. I am not averaging last round's four YAML votes with the two JSON votes: none of the four said how a standard-library-only tool parses YAML, so a YAML file adds a named parser and a dependency to a tool whose whole constraint is that it has neither. My #2 — 「故用兵之法，無恃其不來，恃吾有以待之；無恃其不攻，恃吾有所不可攻也。」 (quoted) — rely on what the interpreter already carries, not on what a machine happens to have installed.

3. **D1, schema — the requirement already names the fields.** Rd3.1a says "with its unit and its basis (measured, documented, or an example)", so `unit` takes `lines`, `utf8_bytes`, `utf16_code_units` or `tokens`, and `basis` takes exactly those three words; I add only `agent`, `version`, `source`, `date`, `limits` and an optional `files`. My #16 — 「約束不明，申令不熟，將之罪也」 (quoted) — a hand-edited file without named fields makes every editor invent the order, and the fault is the giver's. One row:

```json
{"agent": "agy", "version": "1.4.0", "basis": "documented",
 "source": "docs/memory-system/CACHES.md, agy row: 24,000 bytes per rule file; 20,000-token budget",
 "date": "2026-10-18",
 "limits": [{"value": 24000, "unit": "utf8_bytes"},
            {"value": 20000, "unit": "tokens"}]}
```

One row per agent, not per limit, so a duplicated `agent` is a mistake the parser rejects (`object_pairs_hook`, named in the research). `version` is the engine the basis refers to (`"not stated"` when the source does not name one, and required for `measured`). `files`, when present, is the other start files whose bytes count with `INDEX.md`; absent, the limit is on `INDEX.md` alone. The tool measures the rendered index in lines, UTF-8 bytes and UTF-16 code units, compares every limit it can compute in that limit's own unit, prints the binding row with its `basis`, and reports a `tokens` limit as "not checked" — a standard-library tool cannot count tokens. **Wording:** Rd3.1a's "in one file the tool reads" becomes "in `project-memory/limits.json`, one row per agent: `agent`, `version`, `basis`, `source`, `date`, and `limits` (each `value` and `unit`), with `files` for a combined start load"; B4.1 points to that file instead of restating the example.

4. **D2 — the example is a fallback, not a switch.** Row by row: `measured` or `documented` binds; `example` holds Rd3.1b's 200 lines and 24,000 bytes. My #19 — 「死地則戰。」 (quoted) — name the ground and the action follows; here name the `basis` and the limit follows, without a second rule for each engine. My #6 — 「是故智者之慮，必雜於利害」 (quoted) — the harm of the global switch is an unbounded index when the file is partial; the harm of row-by-row is a stale example on one row, which is visible and bounded.

5. **D2 — a missing file, a malformed file, and an unlisted reader are three different facts.** Missing → the example applies to `INDEX.md` and the report says "interim (Rd3.1b)". Malformed → stop and name the row and field; a silent fallback lets a typo weaken a MUST. An agent with no row → it is not in the owner's declaration, so no limit applies; the tool cannot discover a reader the file does not name, so every run prints the declared readers and the reviewer checks that set against the routing. My #4 — 「知彼知己，百戰不殆」 (quoted) — the tool knows the rows and itself; the report must say what it cannot see. An empty `agents` list is a valid declaration of no readers and must be printed loudly, not treated as malformed.

6. **D2 — a documented row ends the example; it does not become a measurement.** Rd3.1a's own words are "measured, documented, or an example" and "A documented figure is not a measurement of the installed engine" (quoted from the YAML). So a documented row binds at its value, labelled `documented`, and is re-read when `version` changes; only a sentinel test may write `measured`. This answers last round's open question the way the record's own vocabulary already does, and it lets the file be written today, when nothing is measured. **Wording:** Rd3.1a's last sentence becomes "A row whose `basis` is `example`, and the whole file when it is absent, holds the example in Rd3.1b"; its `fails_if` parenthetical becomes "(for a row with `basis: example`, or with no file, the example)"; Rd3.1b's last sentence becomes "the tool holds 200 lines and 24,000 bytes as that example and as the fallback when the file is absent."

7. **D3 — keep both new paths, because the two harms are not equal.** W6.3a's body says "every `covers` path either side wrote" and its `fails_if` names a path "one side added" (my reading of the record, YAML:451–466). Both new paths were written and added, so keeping both satisfies both sentences; the old path was changed by both sides, so the "other left it alone" case does not apply and it stays removed. My #6 again: an over-broad `covers` makes an agent read one entry it did not need (a small cost); an under-broad one makes an agent edit a covered file without reading its entry, breaking Rd4.1 silently. Keep the cheap harm. The repository's current contents cannot arbitrate: at merge time it shows one side's view, and under `--check <rev>` "exists" depends on the revision asked (my reading). The report is the second half: two corrections of one path need a person, and W6.3a already sends two supersessions of one entry to `state.md` and the owner (Rd5.3). **Wording:** after "every `covers` path either side wrote", add "When both sides changed the same `covers` path, the merge keeps both new paths, keeps that path removed, keeps each side's `changed:` line, and reports the clash in the task's `state.md` for the project owner. Neither the merger nor the repository's current contents chooses between the new paths." Add to `fails_if`: "or a same-path `covers` clash drops one side's new path, restores the path both sides replaced, or goes unreported."

8. **D4 — the small check lands where the commit already is.** `.githooks/pre-commit:19` runs `python3 tools/memory_index.py --check`, so a scan inside the tool runs on every commit that touches `project-memory/` with no install and no second hook. My #3 — 「不戰而屈人之兵，善之善者也。」 (quoted) — the check that arrives without a new campaign. My #8 — 「故兵聞拙速，未睹巧之久也。」 (quoted) — the short regex table now, not the install campaign later. My #2 again — rely on `re` in the interpreter, not on brew, Docker or Go being present: the research found none of gitleaks, trufflehog or detect-secrets installed here (`which`, ran), and gitleaks is now "feature complete" while trufflehog's live check makes network calls.

9. **D4 — fixed prefixes only, and the reviewer keeps the rest.** The research's table gives the precise formats; I keep AWS access key IDs, private-key blocks, GitHub, GitLab, Slack, Anthropic, OpenAI, Stripe and Google API keys, and drop the entropy rules, `generic-api-key` and JWT. A knowledge repository cites commit ids and UUIDs, which are exactly what an entropy rule flags (research, my reading); `generic-api-key` needs its allowlists to be usable; a JWT's shape is often not a secret. My #6 again — one waived line is cheap, a check that blocks commits on a commit hash is not. The scanner reports path, line and rule name, never the matched value; `secret-scan:allow` on a line skips it and the report counts the waivers, so the reviewer sees them. **Wording:** the YAML's `secret scanner` check becomes "a scanner over `project-memory/entries/` finds it: `python3 tools/memory_index.py` scans the entries and the index it renders for the fixed-prefix credential formats in its `SECRET_PATTERNS` table (AWS access key IDs, private key blocks, GitHub, GitLab, Slack, Anthropic, OpenAI, Stripe and Google API keys). A line carrying `secret-scan:allow` is skipped and counted in the report. The reviewer remains the check for what the patterns do not cover: passwords, tokens with no fixed prefix, and personal data." Add C3 to `docs/index-md/REQUIREMENTS.md`: C3.1 fixed prefixes only, no entropy, no generic rule; C3.2 both modes scan what that mode already reads (working tree in write mode, the snapshot in `--check <rev>`); C3.3 a hit stops write mode before it writes and fails check mode, naming file, line and rule; C3.4 one test per format family, a control commit id and UUID that must pass, and a waived line that must be counted. C1.2 gains "and the scan finds nothing unwaived".

10. **D5 — measure agy now, one run, because its number is the design's number.** `agy --version` gives 1.4.0 on this machine (ran); the tool's comment says `MAX_BYTES = 24_000` is the agy row's "24,000 bytes per rule file" (`tools/memory_index.py:33-36`), and the research's other figure is 12,000 characters, reported and lower (W-4). So the one byte figure the whole design rests on is the one in doubt. My #1 — 「多算勝，少算不勝，而況於無算乎？」 (quoted) and its chain 「地生度，度生量，量生數，數生稱，稱生勝。」 (quoted) — the weighing comes after the measurement. My #17 — 「故策之而知得失之計，作之而知動靜之理，形之而知死生之地，角之而知有餘不足之處。」 (quoted) — probe and read the sign; a page is not the installed engine. My #5 — 「合於利而動，不合於利而止。」 (quoted) — one engine while its number is the one in use; the others wait until one is a declared reader.

11. **D5, method — a control first, sentinels at known offsets, and the unit separated.** Put the test file at the path agy 1.4.0 actually loads at session start, and record that path. Bracket the two documented figures with test sizes, not new limits: 12,000 characters (ASCII, so 12,000 bytes), 12,001 characters, 24,000 bytes, 24,001 bytes; a non-ASCII file of 12,000 characters separates characters from UTF-8 bytes. Each file ends with a unique sentinel; a control of 1,000 characters (a test size, not a limit) must arrive first. Ask agy to print the sentinel (`agy -p`, a one-line prompt). If the control fails, the load path is wrong: record nothing and fix the path. If it passes, the largest size whose sentinel arrives is a measured lower bound and the smallest that does not is the upper bound; record both in `source`, put the lower bound in `limit`, and record `agy --version`, the command and the date. Run each size twice; a size that differs between runs is flaky and is not a limit. If 12,000 characters fails, bisect down to the control; if 24,000 bytes passes, do not claim a higher limit without a failing size. The row becomes `basis: measured`; the token budget stays `tokens`/`documented` and "not checked", because this test cannot count tokens. If agy measures above the Claude and Qwen figures, agy leaves the binding set and Claude's "25KB" (25,000 or 25,600, unstated) becomes the next question — the test does not settle that, and I will not guess it.

12. **Proposed change to the pattern.** A check that reads a value prints the row's `basis` in its result, so an `example` or `documented` row can never pass silently as a measurement; and a measurement brief names a control whose failure voids the result instead of reporting a limit. This is my #4 and my #17 applied to the run's own reports.

## What I need to know

1. **Which path does agy 1.4.0 load at session start in the projects that will use the kit, and does `INDEX.md` reach it by that path?** If agy does not load `INDEX.md` at start, the measured row is not a limit on `INDEX.md`: the method stands, the row is removed.
2. **May a `documented` row replace the example, or must the row wait for a measurement?** I read Rd3.1a's "measured, documented, or an example" as yes; if the owner says measured only, every documented row stays on the example until D5's method is run for it. This is the one place `who_decides` can flip D2.
3. **Is the first project's declared reader set empty, or which engines are in it?** If empty, `{"agents": []}` is a valid declaration and no start-file limit applies; the report must say so loudly.
4. **Does the owner want the secret scan to stop write mode as well as `--check`?** I recommend both, so a credential is not copied into `INDEX.md` once before the commit gate stops it.

## Costs and risks

- **D1** — JSON has no comments and punishes a missing quote or comma; `source` and `basis` carry what a comment would, but the owner still hand-edits a strict format. A `tokens` row and a combined `files` row are recorded but only partly checked, so the reviewer pays the rest. (my #1, my #16; *not measured*: how often the owner edits it)
- **D2** — a documented figure can be too high for the installed version, and then the reader cuts `INDEX.md`, not the check; the requirement says so itself. Row-by-row also lets an undeclared reader pass; only the owner's declaration and the reviewer's check close that. (my #2, my #4, my #6)
- **D3** — keeping both new paths can leave a stale `covers` path, so an agent may read an entry it does not need, and the merge waits for the owner, which can block a task. The alternative silently loses a path a side wrote. (my #6, my #16)
- **D4** — a fixed-prefix match can be a quoted example, so a commit blocks until the line is waived; the waiver is a place a real key can hide, which is why the report counts it; passwords, no-prefix tokens and personal data still pass. The tool gains a second job and grows, and its tests must cover both modes. (my #6, my #8, my #4)
- **D5** — the run costs agy calls and goes stale on an upgrade (the `version` field is what makes that visible); it measures one path and one unit and cannot measure the 20,000-token budget; a wrong path measures nothing, which is why the control's failure voids the run. (my #17, my #2, my #5)

## How we would know I was right

- **D1:** a three-row `limits.json` produces a report whose binding line names the row, its value, unit and `basis`; a duplicate `agent` fails; a row with `unit: "weeks"` fails naming the row; a `tokens` row is reported "not checked"; `--check <rev>` reads the file at that rev, not the working tree.
- **D2:** with no file, a 201-line index fails and the report says "interim (Rd3.1b)"; with a `measured` row at 300 lines and an index of 160 lines, the 160 passes and the report names that row and its date; a row with `basis: example` still fails at 201 lines; a malformed file fails with the row's name, not a traceback; the report lists the declared readers, so an omission is visible.
- **D3:** two branches, one replacing `covers` P with Q and one replacing P with R, merge to a file holding Q and R, not P, with both `changed:` lines, and `state.md` holding the clash; a merge that restores P or drops Q fails review.
- **D4:** one synthetic sample of each fixed-prefix family in a test entry is found each time, reported by file, line and rule, with the value not echoed; a commit id and a UUID pass; a `secret-scan:allow` line is skipped and counted; a plain password passes the scan — the sentence that says what the check does not establish.
- **D5:** the control's sentinel arrives; the 12,000-character file's sentinel arrives; the 12,001-character file's does not — the limit lies between them and is recorded with its unit, version, command and date. A failed control records no limit. A later `agy --version` that differs from the row's `version` sends the row back to the test.
