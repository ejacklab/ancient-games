# N2 — Add two features to tools/memory_index.py (coder)

You change one existing script so it meets new requirements. The acceptance tests that define "done" are already
written and frozen; make them pass.

## The spec (read first)

`docs/index-md/REQUIREMENTS.md`:
- **B2.8** — an entry holding a known credential (the fixed-prefix forms listed there) is an error in every status,
  in both modes, reported as `<file>: possible credential (<kind>) on line <n>` **without the matched text**. No
  entropy or keyword rule, no waiver. B2.5 and the B2 Fails if name it too.
- **B4.1, B4.2, B4.5** — the limits come from `project-memory/start-limits.json` (a JSON object, `limits` a non-empty
  list of rows with `agent`, `unit` in `lines`/`bytes`/`characters`, `limit` a whole number above 0, `basis` in
  `measured`/`documented`/`example`, `source`). For each unit the smallest row applies; a unit with no row keeps the
  example (`MAX_LINES` 200, `MAX_BYTES` 24,000). With no file, the example applies and the run says so. A bad file is
  an error `project-memory/start-limits.json: <problem>` in both modes, never a silent fallback. Check mode reads the
  file from the same snapshot as the entries (the staging area, or the commit named), never the working tree. The
  exact printed lines are in B4.2.

`docs/index-md/DESIGN.md` steps 5 and 7 say where each fits.

Points to hold:
- Standard library only (`json` is fine). Python 3.10 must work.
- Compile the credential patterns once, at the top, with a comment citing B2.8; never print the matched value.
- Read the limits file in check mode the same way the entries are read from the snapshot (`git` objects), not from
  disk.
- Keep the existing output for runs that do not involve these features: every older test must still pass.
