# 孫子 (Sun Tzu) — eight calls on the code map

## Answer

Take the COO's eight picks — **a, a, c, b, b, a, c, b** — with `known` owned by evidence (a place from code or description, a link from the type checker), a level counted only by a call link, and the opencode values passed by the run rather than built into the tool. Two wording guards travel with them: A2's missing-link line reads `a known link within the depth is missing with no limit at its site naming why`, and the tool's and agent's duties stay as separate Fails-if lines inside one A2 and one A5.

| # | My pick | One-line reason |
|---|---|---|
| 1 | **a** — not missing when a limit at its site names why | A named `dynamic` limit is a sign, not a silent gap; only an unstated miss should fail A2 (my #17, my #2). |
| 2 | **a** — a body written into a call adds no level | A level is a call link; entering the body adds no link, so the default six counts six real calls (my #1, my #16). |
| 3 | **c** — place from code or description; link from the type checker | `find` locates a place from code or words, while R2 and the vision's typed services make the type checker the ground for a link (my #4, my #17). |
| 4 | **b** — no extra A5 sentence | `its limits` already covers the interface-required limit; a second sentence creates a second owner for one duty (my #16, my #6). |
| 5 | **b** — a tool line and an agent line | Each line charges the actor that acts, and A2 and A5 stay one requirement each (my #16, my #3). |
| 6 | **a** — `exclude` on opencode | A test that swaps in a fake reaches the fake, not the real function; counting it would overstate reach (my #4, my #14). |
| 7 | **c** — one user glob per group, with the interface/tag rule choosing the three globs | A1 says the user fixes the sibling rule, and `--siblings <glob>` is that rule (my #2, my #13). |
| 8 | **b in the tool; a as the opencode value** | The tool has no test convention; the run passes the rule a names, not a built-in default (my #16, my #5). |

## How I decided

1. **My #1 — count the board before a move.** 「多算勝，少算不勝，而況於無算乎？」 (my #1, `quoted`). I set each decision against the line it must move: A2's missing-link and depth lines, A5's `without its evidence or limits`, A3's `the count differs from the list` and `a test with a known path is missing`, A1's sibling table. A pick that cannot be charged to one of those lines is not a decision yet. The frame is my reading; the quote is from my list.

2. **My #4 and my #17 — know the other and yourself; probe each thing by its own sign.** 「知彼知己，百戰不殆」 (my #4, `quoted`); 「策之而知得失之計」 (my #17, `quoted`). For (3), the vision gives two grounds, not one: `find` locates a place from code or a description, while R2 follows a call through the type checker, and the vision says TypeScript is chosen because a syntax-only reader cannot follow `yield* Permission.Service`. I take c. It is a change from my round-2 wording: b widens `known` to repository source as well as type information, so a source-only reading could call a link known and the key writer's method, not the type checker, would decide; c gives each object the evidence it can have. If `known` must also govern A1 and L2, c is too narrow for A1's checked example, and I would go back to b — that is the one question below.

3. **My #17 and my #2 — a named sign is not a silent gap; do not rest on the other side's restraint.** 「策之而知得失之計」 (my #17, `quoted`); 「無恃其不來，恃吾有以待之」 (my #2, `quoted`). For (1), a link the tool marks `dynamic` with a limit at its site has said why it stopped. A2 already requires each link to give its kind and location; L1 requires every branch that stops early to name why. The miss A2 should catch is the one with no limit at its site. So a, with 范蠡's condition. I read `naming why` as the `reason` field; `text` is optional detail. The condition is load-bearing: a false `dynamic` label on a static link must fail as a false limit (L1/A5), or the carve-out becomes a hiding place.

4. **My #1 — the chain's steps are its units.** 「地生度，度生量，量生數，數生稱，稱生勝。」 (my #1, `quoted`). For (2), the chain is built of call links; the spec's `ChainStep` carries one `link` per step, and a body written into a call is entered by the same call expression, not by a new link. So a. The COO's reading that b would halve the reach of six is not measured; I do not use it as a fact, only as the price of b if it were chosen.

5. **My #16 and my #6 — clear orders; mix the harm into the benefit.** 「約束不明，申令不熟，將之罪也」 (my #16, `quoted`); 「智者之慮，必雜於利害」 (my #6, `quoted`). For (4), `its limits` is the answer's limits; the spec's `Limit` type includes `other`, and the no-`--tests` limit is exactly that. A second sentence saying an interface-required limit is part of the answer adds a second owner for one duty, and its only benefit is against a narrow reading of `its limits` that the type does not support. So b. The harm is that a reader can still read `its limits` as only stop-early reasons; the spec's type is the guard.

6. **My #16 — once the order is clear, charge the one who fails it.** 「既已明而不如法者，吏士之罪也」 (my #16, `quoted`). For (5), the tool and the agent are two actors with two checks — the evaluator and P6. One line naming both cannot be marked MET or NOT MET for one actor; two labelled lines can. The requirement stays whole: the lines are its Fails-if list, not two requirements. So b.

7. **My #4 and my #14 — know what a test actually reaches; numbers are not the goal.** 「知彼知己，百戰不殆」 (my #4, `quoted`); 「兵非貴益多也」 (my #14, `quoted`). For (6), a test that swaps a fake service has a static path to the fake, not to the real function. Counting it would say the real function is reached when it is not; A3 fails when the count differs from the list or a test with a known path is missing, and a fake path is not a known path to the real function. So a. c would report more, but it is a third behaviour beside the user's `count|exclude` rule, and the spec's `TestsAnswer` has no field for it.

8. **My #2 and my #13 — rely on the preparation you own; not every road is taken.** 「無恃其不來，恃吾有以待之」 (my #2, `quoted`); 「途有所不由，軍有所不擊，城有所不攻，地有所不爭，君命有所不受。」 (my #13, `quoted`). For (7), A1 says the sibling rule is fixed by the user, and the spec already takes `--siblings <glob>` with no default. c is that rule. The interface/tag test is the right way to choose the globs for the three modules, not a run-time discovery rule; a tool that discovers siblings is guessing the user's rule, and a wrong guess is silent. So c, with that cost named.

9. **My #5 and my #16 — state the rule, then move on it.** 「合於利而動，不合於利而止」 (my #5, `quoted`). For (8), the spec says which files are test files is set by the user and the tool has no default. b keeps the tool honest and attaches the no-test-pattern limit when the user is silent. a is a good value for opencode, not a good default for every repository: a `*.spec.ts` outside `test/` or `__tests__/` is missed, and only the user's glob can know it. 10. **My #3, my #8 and my #14 — keep the requirement whole; value the decision, not the duration; numbers are not the goal.** 「全國為上，破國次之」 (my #3, `quoted`); 「故兵聞拙速，未睹巧之久也」 (my #8, `quoted`); 「兵非貴益多也」 (my #14, `quoted`). That last sentence is my reading of the pattern, not a quote. ## Costs and risks

1. **(1) A false `dynamic` label is the loophole (my #2, my #17).** The wording trusts the limit at the site. A tool that labels a static link dynamic and omits it will not fail A2's missing-link line. The guard is outside A2: L1 and A5 must fail a limit whose why is false. If no check owns that, a is a hiding place and b is safer despite its cost.
2. **(2) Levels stop tracking lexical nesting (my #1, my #16).** A body written into a call and its surrounding function can both be level 0 for a chain, because the body is entered by the call expression, not a link. A reader who takes six levels as six nested bodies will misread; the requirement must say the unit is call links. The COO's half-reach under b is not measured, so b's price is unknown, not zero.
3. **(3) A link the type checker cannot establish is not `known` (my #4, my #2).** Precision costs coverage: a link a human sees in source but the type checker cannot establish will not fail A2 as missing. R2's unresolved and ambiguous labels and L1 carry it, but A2's missing-link line will not. For a place found from a vague description, pointing to it is only as sharp as the description; the ambiguity flag is the guard.
4. **(4) `its limits` must be read as the interface's `Limit` type (my #16, my #6).** If a reader takes it as only stop-early reasons, the no-`--tests` limit has no owner. The spec's `Limit` type includes `other`, and A5's `without its evidence or limits` is the line; but the requirement does not say interface, so a narrow reader can disagree. The cost is a reading, not a code change.
5. **(5) Two lines mean two strings and a partial report (my #16, my #3).** Every case that names an A2 or A5 line must be re-mapped, and the agent's lines are NOT CHECKED → P6 until the integration test runs. A2 and A5 stay one requirement each, but the report reads tool MET, agent NOT CHECKED, which is honest and incomplete.
6. **(6) The fake-path tests disappear (my #6, my #14).** With a, a test that swaps a fake is in neither the count nor the list; a reader may conclude no test touches the area. The count is true for tests that reach the real function, but the picture is incomplete. If the user needs the fake path, they must run with `--fake-rule count`, which inflates the count; c avoids the trade but adds a third behaviour to a two-value rule.
7. **(7) A wrong glob is silent (my #2, my #13).** The user's glob is the only rule; if it names the wrong set, the sibling table loses files and no limit fires — the no-glob case has a limit, a wrong glob does not. Files that share an interface across folders are missed unless the globs include them. The three globs are the COO's to write; until they are written, c is a rule without its opencode instances.
8. **(8) The tool cannot know a test file without the user's value (my #5, my #16).** With no `--tests`, every answer whose content changes carries the limit, which is safe but noisy; the opencode value can drift, and a `*.spec.ts` outside `test/` or `__tests__/` is missed. The value is a run input, not a tool default, so the run must pass it every time.

**Proposed change to the pattern.** When the owner overrules a pick, write the reversing condition beside the pick in the run's state file and re-map the affected Fails-if strings before the next round. It would change what happens after an overrule: today the condition lives in an expert's answer, and the next agent must re-read the answers to find it; the change keeps the case strings and the requirement text in step and gives the next agent the overrule in one place.

## How we would know I was right

1. **A dynamic call with a known target (1).** A fixture where a key writer can name the target and the tool cannot follow it: the answer carries a `dynamic` limit at the site, and A2's missing-link line passes; delete the limit and the same answer fails; put the limit on a link the type checker establishes statically and L1/A5 fail the false why.
2. **A body written into a call (2).** A fixture with `Effect.fn("name")(function* () { ... })`: `chain --down 1` from the caller shows the body's call at level 1, not level 2; the same code with a named holder gives the same links and levels; on opencode, the default six reaches the same set of real calls as a hand count of six call links.
3. **A place from words, a link from types (3).** `where` and `find` return a place named by code or description; a link the type checker establishes and the tool omits fails A2; a link only a regex could claim is not marked missing; a key written by another agent from source and type yields the same known set.
4. **No `--tests` (4).** The `tests` answer carries `{reason: "other", text: "no test-file pattern given"}`; a copy that drops it fails A5's `without its evidence or limits`; a correct answer with it passes.
5. **Two actors, two verdicts (5).** The report has separate MET or NOT MET for the tool's and the agent's lines in A2 and A5; the agent lines are NOT CHECKED → P6 until the integration test; no tool failure charges an agent line.
6. **Fake rule on opencode (6).** With `--fake-rule exclude`, a function whose service a test fakes returns a count equal to its list and no fake-path test; with `count`, the fake-path test appears; a test using the real service appears in both; the count matches a key written by another agent.
7. **Sibling globs (7).** `map` on the three modules with the chosen globs returns a sibling table whose rows match a key written from the interface/tag rule; removing a file from a glob removes it from the table; a file in another folder with the same tag is not in it — the known cost.
8. **Test-file value on opencode (8).** With the value, `tests` returns the known tests; a `*.spec.ts` outside `test/` is absent — the known cost; with no `--tests`, no file is a test and the limit appears.

**What these checks do not establish.** They do not show that the map costs fewer tokens than reading and grepping; that is L2's measure, on the same module and questions, with correctness keys written by another agent. They also do not show that b's half-reach or the three globs are right on opencode; those are not measured here.
