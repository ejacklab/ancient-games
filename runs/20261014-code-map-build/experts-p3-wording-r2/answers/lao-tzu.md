**Final A2 — the call chain through one place**

> **A2 The call chain through one place.** Given code or a description, the tool locates the place and returns its caller and callee chains, counted in levels from the place. The user sets the depth each way; when the user does not, it is six. In this requirement a place is known when the given code or description points to it, and a link is known when the type checker establishes it. A link's level is its shortest call distance from the place, so every known link within the selected depth is shown, whichever order the tool walks. When more than one place matches, the tool flags the match as ambiguous and lists every candidate with its location; the agent picks the place that fits the question best, builds its chain, and names every other candidate it did not build. Each link names the body that holds the call, and gives its kind and its location. A body written straight into a call is a place of its own; the function that surrounds it is not shown as the caller of its calls. A function reached twice is shown once, with a reference back, and a link reachable through a shorter route is still shown.
>
> **Fails if:** any of these happens:
> - a known place is not found;
> - by the tool — an ambiguous match is not flagged, or a matching candidate is not listed with its location;
> - by the agent, checked in P6 — an ambiguous match is treated as certain, or a candidate the agent did not build is not named;
> - a known link within the depth is missing, or a shown link contradicts the code;
> - a link lacks its kind or location;
> - a function reached twice is shown twice, or its reference back is missing or does not say where it is shown.

**Final A5 — one question, one answer**

> **A5 One question, one answer.** A specific question gets that whole answer with its evidence and limits, not a whole-map dump, and gets it in the form the tool answers in — JSON, or the default text the agent reads. That answer holds the result that was asked for, its evidence, its limits and the candidates it returns when it flags an ambiguous match, and nothing the command does not answer, whether in another section or inside the answer itself. A limit the interface requires for that command is part of the answer. A whole map is produced only when the user asks for a module map, and `map` is the only command that returns one.
>
> **Fails if:** any of these happens:
> - by the tool — an answer comes inside a dump, or holds content the command does not answer, whether in another section or inside the answer itself, or comes without its evidence or its limits; or a command other than `map` returns a whole module map;
> - by the agent, checked in P6 — the agent runs `map` when the user did not ask for a module map.

**范蠡's dynamic question is answered by the wording, not by the owner.** With "a link is known when the type checker establishes it", a dynamic target is not known, so its absence cannot fail A2's missing-link line; R2 ("an unresolved or ambiguous target is unmarked") and L1 carry it, and `A2-computed-member` still passes because it charges "a shown link contradicts the code". If the owner widens "known", then that bullet must read "a known link within the depth is missing with no limit at its site naming why" — 范蠡's conditional wording, which I accept as given.
