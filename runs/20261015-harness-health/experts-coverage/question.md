## Facts

**EJ's process, in their words** (quoted, 2026-10-15): "for me normally I get requirement, I will gen use cases, and also see old use cases cover this requirement or not. and use AI to gen out all possibily, but actually not all require to be covered. so we get the 80% of all the possibility will do." And earlier: "80% is our target to achieve, how I image is you will gen a plan or a eva for a requirement, then we will looks at the test coverage, why 80% those very basic things and 1 in a million edge cases those doesn't required to test."

So, as steps:
1. A requirement arrives.
2. Use cases are written for it.
3. Old use cases are checked: do any already cover this requirement?
4. An AI generates all the possibilities (cases) for the requirement.
5. Tests cover about 80% of those possibilities. The very basic cases must be covered; one-in-a-million edge cases need not be.
6. 80% is a **target**, not a gate that stops work. It is EJ's number, not measured (n=0).

**The current draft rule** (main agent's wording from EJ's statements, *proposed*):

> **R11.1** For each requirement, an eval plan is written that lists the cases showing the requirement met or broken, each marked **basic** or **rare**. The target is that tests cover at least 80% of the listed cases, and every case left uncovered is a rare one.

The clause "every case left uncovered is a rare one" was added by the main agent, not by EJ, so that 80% cannot be reached by testing easy cases while a basic case goes untested.

**A weak spot the main agent sees** (*its reading*, not measured): a list generated by AI has no fixed size. The same requirement can produce 15 cases or 60 depending on the prompt and the run. If the list fills with small variants of the basic cases, 80% is easy without much testing; if it fills with exotic cases, 80% forces testing the rare ones EJ meant to skip. So the percentage moves with the generator, not only with the testing.

**Open question:** who marks a case basic or rare? The main agent's proposal: the agent writing the eval plan marks them and EJ reviews only the rare list (what will go untested). Alternatives: the independent reviewer marks them; EJ marks each one.
