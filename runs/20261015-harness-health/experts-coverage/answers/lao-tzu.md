# 老子 (Laozi) — Does the 80% coverage target hold up?

## Answer

It holds that not everything is tested and that the list must be cut, not filled; it breaks at the percentage, because a fraction over a list nobody bounded is decided by the generator rather than by the testing. My proposal: keep EJ's 80% but count it over the cases the requirement itself names (so the denominator is not the AI's output), and replace the per-case basic/rare mark with one written sentence naming what is not tested — the open question then has no one to mark each case, because a case whose wording comes from the requirement cannot be demoted, and only the plan-writer (not EJ, not the reviewer) may exclude what the requirement does not name.

## How I decided

1. **My #1** (algorithm; `quoted`) — 損之又損，以至於無為。無為而無不為. The words give a repeated subtraction that reaches an end state, not a fraction. "With not-doing, nothing is left undone" makes the test for having cut enough: does what remains still show the requirement met or broken.80% never arrives — it leaves a fifth of the list to be re-argued every run, and 80% is not the thing the chapter stops at.
2. **My #14** (`quoted`) — 少則得，多則惑. A list of 60 in which 50 are variants of the basics is confusion, not coverage. The main agent's weak spot is right, but the fix is not a number bounding the generator's output (house rule). The fix is that the denominator must not be the generator's output.
3. **My #16** (`quoted`) — 知人者智，自知者明; 勝人者有力，自勝者強, and the item's own note that these are eight parallel statements, not a ladder. Counting over possibilities the generator invented is knowing others' cleverness; counting over the requirement's own cases is clarity. So: counted over the requirement's named cases.
4. **My # #8** (`quoted`) — 知不知上，不知知病… 聖人不病，以其病病，是以不病. The step "use AI to gen out all possibily" asserts exhaustive knowledge; that is the sickness the item names. **Concrete break:** the requirement is "the system must never report success on a partial write". The generator returns twelve success-path cases; all pass; 12/12 is 100%, 80% is reached, the run passes — and the one case that can break the requirement was never in the denominator. Nothing fails anywhere.
5. **My #11** (`quoted`) — 反者道之動; 正言若反; 柔弱勝剛強… 天下莫不知莫能行. "One in a million" measures how unlikely the input is; reversal says the soft thing everyone knows and nobody practises is what beats the hard thing. So the test for leaving a case untested is not its frequency but a comparison: if it fires, what does it cost against covering it. That is a comparison, not an invented number.
6. **My #2** (`quoted`) — 知足不辱，知止不殆; 禍莫大於不知足; 始制有名，名亦既有，夫亦將知止，知止所以不殆. Ch. 32 says it in the form the question needs: once the names exist, one knows to stop. The basic/rare names are the 始制有名, so the names are meant to be the stopping point, not a fraction of an unbounded list. My list's Gaps record that 知止 ("stop where?") is unresolved in the sources, so I claim only this: the stop must be nameable. I cannot supply where EJ's stop is.
7. **My #4** (`quoted`) — 天下神器，不可為也… 是以聖人去甚，去奢，去泰; and 為者敗之，執者失之. The whole possibility space is a grip, and gripping loses it. The cut already has a name: 去甚，去奢，去泰 — the extreme, the extravagant, the excessive. EJ's "1 in a million edges need not be tested" is 去奢，去泰 in EJ's own words. What the words do not say is who cuts — that is the open question, answered below. (Guodian 甲 has 為之者敗之，執之者遠之; ch. 29 is not in Guodian.)
8. **My #3** (`quoted`) — 持而盈之，不如其已; 功成而弗居，夫唯弗居，是以不去; 功遂身退，天之道. A list filled to the brim is what ch. 9 warns against, and once a case is covered the work on it is finished: do not dwell on it, do not add a variant. This is also the reuse answer — an old case that already fails the requirement is done, and writing a new one for the same clause is 弗居.
9. **My #10** (`quoted`) — 儉故能廣; 不敢為天下先，故能成器長. Reuse is the frugality that buys breadth, and not daring to be first is what stops a new case being written where an old one already answers.
10. **My #13** (`quoted`) — 善有果而已，不敢以取強; 果而勿矜; 果而不得已. The good one has a result and that is all, and does not use it to take strength. So the coverage number must not be the thing that shows the harness is healthy. Under the rule as drafted a run can print 80% and be read as health; that is the result used to take strength.
11. **My #7** (`quoted`) — 民之從事，常於幾成而敗之。慎終如始，則無敗事; Guodian 丙: 人之敗也，亘于其且成也敗之. **The failure of every coverage plan is at 79%.** Ten basics, nine pass, the tenth is the transition (retry after a partial write) — the run stops because 90% ≥ 80%. So the main agent's clause "every case left uncovered is a rare one" is needed and I support it; but a clause inspected at the end is the wrong place for it. My reading: the condition has to hold when the list is written, not when the run ends.
12. **My #18** (`attributed`) — 吾所以告子，若是而已; 良賈深藏若虛，君子盛德容貌若愚. The decision about what will not be tested should be one short statement. EJ should not read sixty marks; EJ should read the one list of what is not covered.
13. **My #19** (`attributed`) — 以深為根，以約為紀; 堅則毀矣，銳則挫矣; 常寬容於物，不削於人; 苟免於咎. 以約為紀 — restraint as the rule — is the plainest statement of what I am proposing. And 不削於人: a rare mark is not a verdict on the writer, so whoever applies it should not be the writer.
14. **My #9** (`quoted`) — 欲先民，必以身後之; Guodian's form: 圣人之才在民前也，以身后之. Whoever wrote the list stands in front of it. The marking decision should not be handed back to them.
15. **My #17** (`quoted`) — 故有之以為利，無之以為用; 當其無，有車之用. **My reading** (the item's own caution: the words do not say to remove anything): the omitted part is not empty — it is what the covered cases are measured against. Cutting the list changes what the rest of the list means, so the cut is a judgement, not bookkeeping.
16. **My #6** (`quoted`) — 多易必多難; 是以聖人猶難之，故終無難矣; 為之於未有，治之於未亂. A percentage is the easiest plan there is, which is what the chapter says turns into difficulty. And the cheap moment for the case list is before the code exists, not after.
17. **My reading — the better idea, and the check that would show it is better.** For each requirement, the eval plan holds (a) a short list of cases whose wording comes from the requirement's own text — these are basic by construction and each must be able to return fail, and (b) one sentence naming what is not tested and why. 80% is counted over (a) only, so the AI's list size cannot move it. The plan-writer alone may exclude, and only what the requirement does not name; the independent reviewer checks the exclusion sentence against the requirement text and can fail when a case the requirement names has been demoted — which gives the reviewer a check that returns fail (my #13: 善有果而已, and the earlier agreement that a judge counts only if it can return fail). Nothing here is a safety bound, so this is a SHOULD, not a MUST. **The check:** generate the case list twice for one requirement with different prompts and diff the two named basic lists — under the rule as drafted both runs report "80%" and nothing is comparable; under this rule, any case basic in one run and excluded in the other is an unstable mark, and that diff is the finding.

## What I need to know

- Whether the case list is written before the tests run or reconstructed afterwards. If afterwards, the cut is a justification, not a plan, and the whole difference above disappears.
- Whether old use cases carry a recorded pass/fail against the requirement, or only their text. If only text, reuse is gripping rather than verifying (my #4), and I would want the old case run against a broken version before it counts as coverage.
- Whether EJ wants the coverage number to appear in the harness-health result at all (my #13 says it must not be used to take strength; whether it appears is EJ's call, not mine).
- Whether the exclusion is bounded by "the requirement does not name it" (my proposal) or by "a written reason" (the alternative). The first is checkable by anyone; the second is checkable only by the person who wrote the reason.
- Whether a case that is the *only* case able to fail a requirement may ever be excluded. I assume no; that assumption decides the rule, so it is EJ's to confirm.
- Where EJ's stop is. My list's Gaps record 知止 ("stop where?") as unresolved in the sources, so I can say the stop must be nameable but not where it lies.

## Costs and risks

- **A short named list can lose a real case to the person doing the cutting** (my #6: 是以聖人猶難之 — the sage still treats it as difficult). A smaller list will under-report, and the method will read as testing less.
- **Naming only requirement-worded cases excludes the implied-but-un-spelled case** (my #4: 執之者失之 — the grip is exactly where the un-spelled case hides). The more precisely a requirement is worded, the better this works; the vaguer it is, the more it silently excludes.
- **Dropping the per-case mark removes the paper trail.** If an omission later causes harm, there is one sentence of record instead of sixty marks (my #19: 受天下之詬 — take the world's reproach — but a single sentence is a thinner receptacle than a marked list).
- **Restraint as the rule (my #19) will look like under-testing** in a team rewarded for volume of tests, and someone will add cases back to look thorough (my #13: the cost of not using a result to take strength is exactly that the result goes unremarked).
- **Reuse cuts work and also cuts discovery** (my #3: 功遂身退 is about finishing, not about never looking again — my reading). Reuse is safe only if the reused case is run against a broken version; otherwise it is a test that has never been seen to fail.
- **The 80% stays EJ's number, but over my denominator it means something different from what EJ pictured.** That is the largest cost in this answer and it is EJ's decision, not mine.
- **The diff test costs an engine call** (two generations of the same list). House rule: no paid engine call without EJ's go-ahead.

## How we would know I was right

- **Planted wrong input (already a house rule, and it can fail):** take a requirement clause, delete its negative case from the generated list, then run coverage. Under the rule as drafted, 80% is still reached and the run passes. Under this proposal, the exclusion sentence is falsified against the requirement text and the run fails. If the rule as drafted passes that, the 80% is measuring the generator.
- **Generator variance:** one requirement, two prompts, two lists, both runs reporting 80%. If the two named basic lists can be diffed and agree, the mark is stable and the denominator is under control; if a case is basic in one and excluded in the other, the mark is a taste, not a decision.
- **Negative case:** if a run with only the named basics finds a defect that a run over the full list did not find in twice the time, I am wrong.
- **Observable on the artefact itself:** the length of the exclusion sentence against the length of the covered list. If the exclusions outnumber the covered cases, the cut failed (my #18: 吾所以告子，若是而已 — this, and only this).
