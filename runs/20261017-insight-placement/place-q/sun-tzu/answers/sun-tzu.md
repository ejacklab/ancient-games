# 孫子 (Sun Tzu) — where lessons live and how they reach each agent

## Answer
File each lesson once in a private, user-global store — `~/.agents/lessons/`, one file per lesson with a `scope` (all agents or one engine) and `triggers` (the paths, commands or task kinds it bites on) — and keep each project's facts in a committed, path-keyed file at that project's root. Deliver both mechanically, never by asking an agent to remember: the guard hook shows the matching lesson when the main agent writes a matching path, and the brief writer copies the matching rule line into every engine's brief. If EJ wants the lessons public, the same shape moves into this repo and the delivery does not change.

## How I decided
1. I counted what each reader can actually reach before choosing a store (my #1: 「夫未戰而廟算勝者，得算多也；未戰而廟算不勝者，得算少也。多算勝，少算不勝，而況於無算乎？」). Facts: the main agent's lessons sit in one project's Claude Code memory; an engine reads its brief or its working repo; opencode refuses outside-repo paths and agy soft-denies shell and web; the guard is installed once in `~/.claude/settings.json` and roots itself at whatever git repo it is called in (`.claude/skills/workflow-design/guard/SPEC.md` l.22); a skill loads only when its description matches. My reading: no single file is read by all three, so the store's location decides nothing by itself — the gate that pushes it decides.
2. So I chose the gate over the reminder (my #12: 「故善戰者，求之於勢，不責於人，故能擇人而任勢。」). Change the condition under which the lesson appears — at the write, and inside the brief — instead of exhorting the agent to go read. My #2 gives the split: 「故用兵之法，無恃其不來，恃吾有以待之；無恃其不攻，恃吾有所不可攻也。」 Build the side you own; do not rely on the agent's remembering.
3. The gate must read the store from any project, so the store is user-global: `~/.agents/lessons/`, a private git repo, one Markdown file per lesson. Not option (b), a skill in this repo: a skill loads only on a description match, and this repo is public, so a store naming other projects' traps would be published.
4. Do not route delivery through "go read the store" (my #13: 「途有所不由，軍有所不擊，城有所不攻，地有所不爭，君命有所不受。」). A command an engine will not accept is not delivery: opencode and agy cannot read outside their repo, so for them the line must be in the brief text.
5. One-type versus all-agents is a `scope:` field in the lesson file, one directory, no per-engine folders (my #3: 「是故百戰百勝，非善之善者也；不戰而屈人之兵，善之善者也。」 — one copy kept whole beats copies per engine). Scope decides who it is pushed to, not who may read it: the main agent should read every scope, because it has to know an engine's limits to brief it.
6. Project facts are keyed by path, not held in a folder. My reading of the three options: a comment at the line is read only when that line is read and disappears in a refactor; a file in the code's folder drifts and is invisible from the root; the code map is designed, not built, so it can hold nothing today. What is left is one committed file at the repo root, `.agents/lessons.yaml`, mapping a path glob to one line. "Kept with the code" then means reachable from the code's path in one mechanical hop (my #10: avoid the solid, strike the empty — put the fact where the write would otherwise be empty of it, not in a general doc).
7. Every lesson must name its ground (my #19: 「九地之變，屈伸之利，人情之理，不可不察也。」). `triggers:` is required — path globs, command patterns, task kinds. A lesson with no trigger is not filed yet (my #5, 「非利不動」: without an advantage to act on, there is nothing to file).
8. Noise is the price, so cap it: at most two lines per push, one line per lesson; when a lesson becomes a check, the store keeps only a pointer and the check does the enforcing (my #8: 「故兵聞拙速，未睹巧之久也。」 — value the brief's speed over the store's completeness).
9. Delivery 1, the main agent: the guard already sees every Write/Edit/MultiEdit path before it runs and can add a context line (`SPEC.md` M5). Add the lesson match there, and at SessionStart for the project. Delivery 2, engines: a brief section filled by one selector command. **Proposed change to the pattern:** `docs/workflow-templates/node-brief.md` gains "Lessons that bite here", and the brief-writing step runs `lessons-for --repo <path> --paths <paths> --engine <name>` and pastes its output. No engine is asked to fetch anything.
10. Start from the repeats, not the 56 (my #1 counts; my #14: with a small force, do not attack everywhere). The extracted index already shows same-day repeats of a class — F-15cf1278 → F-98c2c4c9 and F-8243a18f → F-96578c5b in `runs/20261017-insight-level/insights.md` — so classify those first and prove the delivery on them (my #17: 「故策之而知得失之計，作之而知動靜之理，形之而知死生之地，角之而知有餘不足之處。」 Probe, then read the sign; do not assume).

## What I need to know
1. Should the lessons be public, as part of the Ancient Games, or private? If public, the store is `agent-lessons/` in this repo, same file shape and same triggers; delivery is unchanged. This is the only answer that moves the store.
2. Does any engine have to browse the store itself, rather than receive two lines in its brief? If yes, the store needs a read-only copy inside each project, because opencode and agy cannot read it where it lives.
3. Is a lesson filed when the insight is written (with all options), or only after EJ picks a fix? Filed before the choice, the store propagates options EJ may decline; I would file only the chosen fix and leave the rest in the run's `insight.md`.

## Costs and risks
- Partial coverage: the guard sees Bash writes only as a command line (fact), so shell edits and heredocs escape the path gate; a lesson keyed to `sed -i` will not fire (my #2: you can make your side ready, you cannot make the mistake certain).
- Over-matching triggers are the likeliest failure and the one EJ has already named; a glob like `**/*.py` would push on every write (my #8: a lesson delivered too slowly is a cost with no gain).
- Rot: a store that never retires a lesson becomes stale advice; a lesson now enforced by a check must be demoted to a pointer (my reading of #15: a general set on holding every position can be moved).
- Divergence: a fact copied into both the store and the project file will disagree one day; the project entry may name the lesson id, never repeat its rule (my #3).
- Migration is real work: 56 sections to classify by scope and trigger, and only EJ can settle each scope; starting at 56 will stall (my #1: more reckoning wins, no reckoning loses).
- False confidence: the hook naming a lesson is not evidence the agent followed it; only a planted repeat tests the delivery (my #17).
- Public exposure: anything filed in this repo is public (fact); a lesson naming a private repo or a vendor quirk must stay in the private store (my #6: deliberation must mix harm with benefit).

## How we would know I was right
Take the two classes that already repeated the same day — the fail-first run check (F-15cf1278 → F-98c2c4c9) and the C4 wording (F-8243a18f → F-96578c5b). On a scratch repo, plant the same trap and run the task without the lesson in the brief. Pass: the selector names the lesson and the brief carries it, or the hook shows it before the write, and the worker does not repeat the trap. Fail: nothing fires, or the worker sees the line and repeats anyway. Then measure over ten runs: no third failure id with the same source and root cause; at most two lessons shown per task; and a first write in a *different* git repo still shows its matching line — that last one is what proves "every project's agents read it."

## Recommended version
1. **Store:** `~/.agents/lessons/` — a private git repo, one Markdown file per lesson: `id`, `scope` (`all` or `engine:<name>`), `triggers` (paths, commands, task kinds), one `rule` line, `project-facts:` pointer; `INDEX.md` generated.
2. **One type vs all:** the `scope` field, one directory, one canonical copy — scope decides who it is pushed to, not who may read it.
3. **Project place:** `.agents/lessons.yaml` committed at the repo root, path glob → one line; the code map reads it when it is built.
4. **Delivery, main agent:** the global guard hook — SessionStart by project, PreToolUse on Write/Edit by matching path, at most two lines.
5. **Delivery, engines:** `node-brief.md` gains "Lessons that bite here", filled from `lessons-for --repo --paths --engine`, at most two rule lines.
