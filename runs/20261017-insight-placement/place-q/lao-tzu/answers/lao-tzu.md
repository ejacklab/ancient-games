# 老子 (Laozi) — where lessons live, and how they reach each agent

## Answer

The store is one user-global folder outside every repo, `~/.agents/lessons/`, with one file per scope — `all.md` and one file per engine type — and one reader and one writer: the main agent. The project place is already decided and I do not reopen it: a lesson about this project's code is an entry under `project-memory/entries/` whose `covers:` names the paths, so "kept with the code" means *named by path*, not *put in the folder* and never a comment on the line. The delivery is the brief, chosen at node-design time — the only channel that reaches all six engines — and a lesson leaves the store the moment a check enforces it.

**Recommended version (the store, the project place, the delivery):**
1. Store: `~/.agents/lessons/` — `all.md` plus `<engine>.md`; main agent is sole writer and sole reader; no engine named → `all.md`.
2. Project place: `project-memory/entries/L-*.md` with `covers:` naming the paths; a comment at the line is never the place.
3. Delivery: lesson text inside the brief of the node whose piece can trigger it, picked when the node is designed.
4. Drain: a lesson that a check now enforces is retired from the store; a lesson every node needs becomes one line in `AGENTS.md`.
5. Never: a skill description match, a hook on every Write, or "go read it".

## How I decided

1. **The store's job is decided by who must read it, and the answer is not the worker — my #9.** The fact set makes every engine *except* one unable to reach a user-global folder: opencode auto-rejects files outside its repo (exit 0, no work), agy soft-denies shell reads. `docs/EXECUTOR_KINDS.md:463-467` is worse than silent — Codex lists `~/.agents/skills` and `~/.codex/skills` but **not** `~/.claude/skills` nor a project `.claude/skills`, and agy "has no working positive control: whether it reads any user skill dir is *unknown*". So a store outside the repo reaches the main agent and maybe Codex and dsh, and cannot reach opencode or agy at all. My #9 says the one who can be above must put himself below in speech — so the store puts itself below every engine and speaks only to the main agent, which is the one reader every engine already depends on (every call is briefed from a file; `WORKFLOW_DESIGN_METHOD.md` §4). **I do not know** whether opencode or agy read any skill dir; nothing in the run settles it.

A lesson is a fact about what happened, not a procedure. Worse, a skill's gate is a description match — the wrong gate for something that must be present *before* the task is known, since "opencode cannot read outside its repo" is needed by the node that would have tried. Option (b) in the question also loses on reach: the seven links in `~/.agents/skills` reach Claude Code, Codex and dsh (`CLAUDE.md:17-19`; I counted 8 entries there, 18 in `~/.claude/skills`), which is three of six, verified.

## Costs and risks

- **Not in git** — no history, no clone, no diff, no PR review of a lesson; and `.gitignore:10` already shows the cost being paid elsewhere: `.harness-guard/` is ignored and `.harness-guard/insights/` is empty, so the guard's own lessons do not survive a fresh clone. *My #14* — 不自見故明: the store claims nothing, and nothing reviews it back.
- **opencode cannot read it at all.** A worker told to go read it will exit 0 and do nothing — the worst possible delivery of a lesson, silent and looking like success. *My #4*: reaching for what should not be reached for loses it. The answer survives this only because no worker reads the store; the moment one must, it breaks.
- **One writer means one point of failure.** If a worker learns something and it never reaches R12.3, it is lost. *My #18* — the counsel is only as good as the reporting.
- **Retirement can cut the wrong thing.** If a lesson is retired before its check exists, the mistake returns and nobody says so. *My #19* — 堅則毀矣，銳則挫矣, and 常寬容於物，不削於人: tolerate, do not pare away. Retirement requires the check to exist first.
- **A lesson that is really a decision or a fact goes stale silently**, because nothing re-reads the store — SoT's own rule is that the *reader* checks, and here no reader is reading. *My #8*: name the sickness, or it is one.
- **I contradict SoT's one-file-per-entry on purpose**, to get one file per scope. The price is that two concurrent writers of the same scope collide on nearly every line and surface as a git conflict in a home folder with no git in it. *My #2*: know what is enough. I traded a merge conflict for a smaller store; one writer is what makes the trade safe, and if that changes the trade is bad.
- **I go against `WORKFLOW_DESIGN_METHOD.md` §4's line** that "files in the repo are the one every tool and every agent can read". I read that line as about project memory — SoT itself puts agent scope outside the repo — but if EJ reads it as covering agent memory, my answer loses, and the skill-in-this-repo version (option b) becomes the answer instead.
- **The 63 memory files are already a third copy** if the store is built without asking what they are for. *My #1*: do not add a place.

## How we would know I was right

1. **The cheapest falsifier, run first.** Dispatch one designed workflow; then read the node's brief file on disk and ask whether it contains any lesson id. Zero briefs carry one → the store is decorative and the whole answer is wrong, whatever else passes.
2. **Planted repeat — EJ's own method, from R12.3** ("A fix that is a check is shown failing on a planted repeat of the failure before it is trusted"). Plant a failure of a kind the store names; the node whose piece can trigger it must carry the lesson's id in its brief **at dispatch time**, and the node whose piece cannot must not. Both halves, because over-delivery fails the same way under-delivery does.
3. **The drain.** After N runs, the store's line count must be flat or falling while the count of enforced checks rises. If the store only rises across N runs, my #1 and #3 are not in force and the noise the owner wants less is being stored, not removed.
4. **The routing.** A lesson filed with no `Seen on:` goes to `all.md`. If such a lesson is later found wrong for a named engine, the routing failed — that single event is the observable, and it is why P2 is a required field and not a convention.
5. **The empty index.** The index must be shorter than the store and must not print lesson text (`insight-index.ts` already does this for run insights). If the index starts carrying bodies, the index has become a second store and my #18 is being read as a licence rather than a limit.
