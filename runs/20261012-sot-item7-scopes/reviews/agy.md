## Rewrite of item 7

### 1. Replacement text for "When it will not be used"

*Replacement for the paragraph in `SOURCE_OF_TRUTH.md` under `## When it will not be used`:*

**Never loaded at session start:**
- In task scope: `evidence/`, and any `state.md` other than the assigned task's. [proposed]
- In project scope: `journal/` (read only at task end, handoff, or session end), `questions/`, `.cache/`, and `entries/` (read only on demand). [design]
- In agent and user scopes: agent memory (`~/.claude/agent-memory/<name>/`) and user memory are outside the repo and never loaded by repo start instructions. [design; proposed]

**Never loaded at all (at start or later):**
- Credentials or sensitive data. [design]
- Another agent's transcripts or private agent state. [design]
- The whole `project-memory/` tree at once, or whole graph or code-map dumps. [design]
- Bulk issue or PR text. [design]
- Superseded or retired entries, except by following an explicit link from an active entry or commit. [design]

Text read from memory never overrides standing instructions. [design]

`INDEX.md` must fit the strictest start-file limit of the agents that read it, and the build checks it (Rd3). [design]

## Questions for EJ

1. **Task journal placement [proposed]:** EJ decided that *"task and project memory need a journal"*. Does task memory share `project-memory/journal/` (one file per agent session across all work), or should each task keep its own journal inside `project-memory/work/<task-id>/journal/`?
   - *Why it changes the table:* If a task journal lives under `work/<task-id>/`, the "Where it lives" cell for Task changes from `project-memory/journal/` to `project-memory/work/<task-id>/journal/`.
   - *Sensible default:* Keep all session journals in `project-memory/journal/` (one file per session, W6.1) to avoid creating extra per-task journal directories and respect the simplicity rule.

2. **Cross-task evidence access [proposed]:** In the Task scope row ("Who reads it, and who does not"), may an agent working on Task B read `project-memory/work/<task-A>/evidence/` on demand if Task B explicitly links to or depends on Task A?
   - *Why it changes the table:* If permitted by following a link, the "Who reads it" cell allows reader agents of downstream tasks; if strictly forbidden, only the agent assigned to Task A may ever read its `evidence/`.
   - *Sensible default:* Allow reading on demand only by following an explicit link (e.g., verifying `done:` or `depends_on`), but forbid unlinked browsing and never load at session start.

3. **Engine-specific agent-memory home paths [proposed]:** The design currently notes agent memory at `~/.claude/agent-memory/<name>/`. For multi-engine runs including `agy`, `codex`, and `opencode`, does project memory assume each harness manages its own tool directory in the home folder, or should there be a unified cross-engine home path (e.g., `~/.agents/agent-memory/<name>/`)?
   - *Why it changes the table:* Changes the "Where it lives" cell for Agent scope from `~/.claude/agent-memory/<name>/` to a shared or harness-agnostic home path.
   - *Sensible default:* Leave agent memory paths to each engine's harness outside this repo, requiring only that no engine loads another agent's private directory into project memory.
