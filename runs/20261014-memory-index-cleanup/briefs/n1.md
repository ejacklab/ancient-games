# N1 — Acceptance tests for two new checks (test writer)

You write acceptance tests from a spec. The script under test, `tools/memory_index.py`, is **not** in this workspace,
on purpose: write the tests from the spec alone. Do not look for the script anywhere else.

## The spec

- `docs/index-md/REQUIREMENTS.md` — the criteria. The ones that changed: **B2.3** (an `id` must be in W1.1's form,
  `DD-MM-xxxxxx-YYYY`), the new **B2.7** (no line starting `<<<<<<<` or `>>>>>>>`), the **B2 Fails if**, and **G4.2**.
- `docs/index-md/DESIGN.md` step 5 — the new errors are errors **for every entry**, in every status.
- `docs/memory-system/SOURCE_OF_TRUTH.md` — W1.1 (the id form) and K6.3 (conflict markers), which the spec cites.

## What to do

Change only `tests/test_memory_index.py`.

1. **Move every fixture id into W1.1's form**: two digits, `-`, two digits, `-`, six lowercase letters or digits,
   `-`, four digits (for example `14-10-a1b2c3-2026`). Once the script rejects other ids, a test that uses an old id
   would fail on its id, or, worse, pass on its id when it means to test something else. Each existing test must
   keep testing what its docstring says, and fail only for its own reason. The places:
   - `write_entry`'s default `id="D-20261012-a1"`, and every expected `INDEX.md` line that shows that id.
   - `INVALID_ENTRIES`: the cases use `id: bad`, `id: ''` and `id: nested-only`. The test that runs them checks only
     the exit code and the file name, so after the change each case would pass on the id alone. Give every case a
     valid id, except a case whose point is the id itself. Move that kind of case into a test that cites B2.3.
   - the `pytest.param` list of malformed active entries (`id: bad`).
   - the B2.5 inactive-warning cases (`id: old`). B2.3 is now an error in every status, so an inactive entry with a
     bad id is no longer a warning.
   - `test_inactive_entries_still_require_id_and_status` and `test_all_validation_problems_are_reported`. These cite
     B2.3, but their status cases use `id: old` and `id: c`, so they would pass on the id alone. An id that a test
     does **not** mean to be bad must be in the form, in a B2.3 test too.
   - ids built at run time, which a lint cannot see: the golden test's `samples` tuple (`entry_id`), the locale test's
     `id=name[:-3]`, and `stage_overflow`'s `id=str(number)` and `id="x"`. Change their expected bytes to match. In
     `stage_overflow`, the overflow must still be real: keep its `assert len(...) > max_...` lines true.
   - every other literal id (`untracked`, `space`, `accent`, `old`, `retired`, `run`, `other`, …).

   Use distinct ids where a test has more than one entry: no two entries may share an id (B2.3).
2. **Add tests for B2.3's form.** These must pass: a good id, and `31-02-a1b2c3-2026` (the check is the form only,
   not the calendar). These must fail: `D-20261012-a1`, `" "`, a random part of five characters, upper case, trailing
   junk (`14-10-a1b2c3-2026x`), and a non-ASCII digit (for example `١٤-10-a1b2c3-2026`). Test each in write mode and
   in check mode (the way `snapshot_args` runs both), and in an active, a superseded and a retired entry.
3. **Add tests for B2.7.** A line starting `<<<<<<<` and a line starting `>>>>>>>` are each an error: in the header
   and in the body, in an active, a superseded and a retired entry, in write and check mode. An error means exit 1,
   `<file name>: ` in the output, no `Traceback`, and `INDEX.md` unchanged. A line that is only `=======` is **not**
   an error (it is also a Markdown heading underline).
4. **Every new test's docstring cites its id** (`B2.3`, `B2.7`, or `G4.2`), in the file's existing style.

Match the file's existing style: its helpers, its parametrize use, its docstrings. No new dependencies.
