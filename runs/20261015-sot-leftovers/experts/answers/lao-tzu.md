# 老子 (Laozi) — which spots can be answered by giving up a step, and what that costs

Three of the five can be answered by giving up a step rather than by resolving them: **U3** wholly (keep the tool's example number, put the reading build in the backlog), **U4** is already given up and needs only recording, and **U2** half (name the decider, leave the enumeration open — the file already names the decider, so the work is one word, not a search). **U1** and **U5** cannot be answered by subtraction: giving them up leaves undone the thing the run exists to do (K4.3's stale-path hole; the design's claim that its paths mean anything outside this repo). ## How I decided

So subtraction has an end point, and the end point is that nothing is left undone. A spot can be given up when what remains undone is already someone's standing decision to leave it undone (recorded, in scope elsewhere). A spot cannot be given up when the undone thing is the run's own objective. Everything below is that one test applied to five rows.
2. **U3 — give it up; the subtraction is already the assumption (my #1).** Keep `MAX_LINES = 200` / `MAX_BYTES = 24_000`, put "build the tool to read limits from a file" in the backlog. The price is named in the YAML header, which already says "There are no fixed numbers: where a limit applies, it is a comparison that measurement decides" — so the in-scope half of U3 is one clause saying the tool's number is the design's example, not a measurement. 4. **U2 — half of it can be given up, and the subtraction is one word (my #2).** 知足不辱，知止不殆，可以長久 — "knowing what is enough, one is not disgraced; knowing to stop, one is not endangered" (`quoted`). ## Costs and risks

- **U1 narrowed to `covers`:** if `source` or `depends_on` goes stale next, the same decision returns and K4.3 is widened twice, which is the harder change (my #2, 甚愛必大費).
- **U1 given up entirely:** every rename costs a whole-entry supersede, and the superseded entry is never deleted — permanent growth in a system whose own point is an audit trail (my #3, the cost of not stopping here is that nothing is ever stopped).
- **U2's enumeration left open:** Rd3.1a is a MUST whose `fails_if` names "the K6 check passes an `INDEX.md` that exceeds it". With no limit named and no decider, the gate can be passed by an example number and fails in the direction that lets a file through which no engine could load. The failure is silent and appears later, as a truncated read in a session (my #4: the limit is not ours to fix by wording).
- **N1 left unrecorded:** `unassigned` becomes a state nothing tracks, and the design stops being able to say which choices are open (my #8).
- **P3 or the plant given up:** the run loses the only check that can see a contradiction, or the only check that can fail on a clean diff (my #7; my #17 by my reading).
- **Every one of these verdicts is cheap to undo** — all of it is text in three files, one commit at the end, `git diff` reverses it (my reading). That is why nothing above needed measuring first, and why U4 stays out.
