# Decision rules — which cache for which question, at query time

Join node 4 of `20261012-caches-enhance`. Merged from three independent engine answers —
`nodes/code-graph.claude.stdout.md` (claude, code graph, `G-F*`), `nodes/vector.codex.stdout.md` (codex, vector index,
`V-F*`), `nodes/sqlite.opencode.stdout.md` (opencode, SQLite FTS5, `S-F*`) — against `recon.md` and
`docs/memory-system/vision-statements/caches-memory-vision-statements.md`.

## The rule

At query time the memory is answered by `INDEX.md`, grep, git and reading the entry; memory stays fully readable with
no cache, and a cache is never the answer to a question the files answer. **SQLite FTS5** is the store for a free-text
question whose words are likely in the entry text, once `INDEX.md` can no longer list every active entry under its size
limit and ranked results with snippets save opened files (`S-F1`, `S-F4`). **The vector index** is for the same
discovery when the question's wording differs from the entry's, once the documented miss trigger has fired
(`V-F11`, `V-F13`, `M4`). **The code graph** is only for a multi-hop structural question about Python code, after its
trigger, and only as a lower bound (`G-F8`, `G-F17`, `G-F18`, `M5`, `R5.3`). None of the three answers a structured
header query (path, status, supersession), an exact identifier, an exhaustive list, proof of absence, history, or
"what is true" — `INDEX.md`, grep, git and reading the entry do, and every cache result stays a candidate until its
source is read (`M19`).

**Thinly or off-brief.** Notes on answer quality, not on the rules.
- **claude** gives the longest and richest cost evidence, but its closing section (its last 12 of 76 lines) is process
  material rather than decision rules: a negotiation with another agent (`ancient-games-1f`) about splitting the work,
  a request that that agent measure the filtered-graph and graph-vs-grep costs, and an explicit statement that every
  command needing approval was refused, so it ran no measurement itself. Its rule ends by labelling itself *"My reading
  of G-F7a, G-F14, G-F17, G-F18, M18, and not measured on this repo."* That disclosed contact with another agent about
  the same question is a caveat on the three answers' independence: claude says it did not open the other engines'
  node files, but it did coordinate with a fourth party on the same brief.
- **opencode** is the thinnest of the three: seven table rows, a rule with no inline evidence id, no `M*` id anywhere,
  and a three-bullet *Not found / Not checked*. It also folds `S-F4`'s vendor BM25 study into its cost table as if it
  measured this project's FTS5/grep tokens; codex and claude both refuse exactly that transfer (§ Where the engines
  disagree, D2/D3).
- **codex** is on-brief and in the exact brief shape, and is the only engine to label part of its own answer
  `model knowledge` (`M6`'s role recommendation) and to run a requirement-check on itself; its note that `0.00 s` is
  the timer's resolution "not proof of zero cost" is the sharpest reading of the recorded numbers.

## Where the engines disagree

No average and no silent winner. `unresolved` means the three files cannot settle it.

- **D1 — What answers a free-text memory question?** opencode: **FTS5 first**, when `INDEX.md` is over capacity and
  ranking matters, with vector only for meaning (`S-F1`, `S-F4`, `S-F3`). codex: **baseline first** — `INDEX.md` and
  grep — then vector "alongside keyword search" when wording mismatch defeats the baseline; codex names **no FTS5**
  anywhere (`V-F11`, `V-F13`, `M4`). claude: **no store at all** for any memory question (`G-F2`, `G-F3`, `G-F10`,
  `M17`, `M19`). **unresolved.**
- **D2 — Is the FTS5/vector benefit measured?** opencode presents FTS5 against grep as a material token saving
  (~5.8K vs ~226K per question; `S-F4`, `S-F13`). codex calls the vector benefit *"guidance, not a measured advantage
  here"* (`V-F11`, `V-F13`, `M4`) and says its synthetic timings *"do not establish vector savings."* claude says
  memory-corpus costs are GAP and there is no head-to-head (`S-F5`, `V-F11`, `G-F10`). **unresolved** — whether
  `S-F4`'s 1,144-document BM25 study transfers to this project's 10,000-entry claim is not settled by the three files.
- **D3 — Token cost of grep + opening hits.** opencode: **~226K per question** at 10,000 entries (`S-F4`, `S-F13`).
  claude: **GAP per question**, "because it depends on hits and grep is unranked". codex: **tokens were not
  measured** (`S-F13`). **unresolved.**
- **D4 — Cost of `INDEX.md` at query time.** claude: **no extra read**, it is loaded at session start (`M17`).
  opencode: **<0.01 s** scan, minimal header-only tokens (`SOURCE_OF_TRUTH.md`). codex: **time GAP and tokens GAP**
  (`M17`, `M19`). Two engines read the same `M17` differently. **unresolved.**
- **D5 — Does `INDEX.md` carry `covers:` (and status) per line?** codex asserts the `covers:` match directly
  (`V-F21`). opencode asserts status per line (`SOURCE_OF_TRUTH:100`). claude hedges: `RECOMMENDATION.md`'s Layout
  says the lines carry `covers`, `SOURCE_OF_TRUTH.md` says only *"one line per active entry"* — so if `covers` is not
  there, that row falls back to grep over `entries/`. **unresolved** (a documentation conflict; the three files do
  not settle which doc is right).
- **D6 — What counts as a fired trigger?** opencode treats a **size crossover (~37K entries)** as a build condition
  (`S-F4`, `S-F5`, `S-F13`). codex treats only a **recorded miss count** as one and says corpus size alone does not
  justify vectors (`V-F11`, `V-F13`, `M4`). claude requires a **demonstrated baseline failure** (`M21`) plus a fired
  R5.3 condition. **unresolved** — the three name three different currencies.
- **Not disagreements, for the record (one engine only, so the table must not read as consensus):** the code graph's
  lane, its triggers and its drift rule rest on claude alone (codex and opencode did not address code structure); the
  `~37K` grep crossover, the `0.0006 s` FTS5 figure and the `~5.8K`/`~226K` token pair rest on opencode alone; the
  vector timings rest on codex alone.
