## Verdict

REPAIR — the regrouping is sound and most of the labels hold, but five requirements are not checkable or not what their sources say: B1.1's "misses" clause cites a benchmark that discards misses, B4.1's reference set disappears the moment B1.1's trigger fires, and B1.2 weakened the vision's test from "finds entries" to "finds an entry".

## Findings

**H1 — B1.1 — "with no more misses" is measured by a benchmark that throws misses away; the citation says the opposite of the clause.** `CACHES.md:367-368`: *"full-text reaches the right entry after reading less than `INDEX.md` plus grep does, with no more misses. Measured as the code-and-docs benchmark was (BM-1 to BM-9): the same questions through both routes, the characters read to the first right entry, and the misses."* The source says: *"A miss is left out, never scored 0"* (`bench/results.md:28`, and `n` differs per route: grep 26, fts 25, vec 19 — so each route's mean is over a different question set). Two further errors in the same sentence: the baseline route in BM is `rg` alone, with no `INDEX.md` arm (`results.md:96-102`), and the corpus was 490 files of this repo's **code and docs**, which `CACHES.md:130-132` says is outside the vision. Severity high. Fix: define the memory-corpus miss once (entry existed, no returned route named it, the agent later opened it) and measure it as a hit count over the recorded questions with a stated denominator; cite BM for the `chars` column only, and say the baseline gains an `INDEX.md` arm that BM did not have.

**H2 — B1 / the rest of `CACHES.md` — the cache now has two different triggers, and the old one survives in five places.** `CACHES.md:356`: *"There are no fixed numbers: where a limit applies, it is a comparison that measurement decides."* Against: `:71` *"once `INDEX.md` can no longer list every active entry under its size limit"*, `:79` *"**FTS5** — conditional on the size trigger"*, `:193` *"`INDEX.md` stops being enough once it can no longer list every active entry under its size limit"*, `:209` *"Built when the trigger fires: `INDEX.md` can no longer list every active entry."* Severity high — a reader of the routing table will build (or not build) on a size limit; a reader of B1 will build on a comparison. Fix: make every one of those five say the B1.1 comparison, and delete "under its size limit" (keep it only as one of the numbered INDEX.md lines in the example table).

**H3 — B4.1 — its check cannot be run once B1.1's trigger has fired, and the trigger violates the sibling design.** `CACHES.md:411-413`: *"The index holds the same set of entries as `INDEX.md`"* / *"**Fails if** the index holds an entry `INDEX.md` does not list as active, lacks one that `INDEX.md` does list…"*. The trigger for building this cache is that `INDEX.md` can no longer list every active entry (`:71`, `:209`), so the reference set is gone exactly when the requirement starts to matter; and the size limit it crosses is itself a requirement in the sibling design: *"**Rd3.1** `INDEX.md` fits the strictest start-file limit among the agents that work on the project, and the build checks it … **Fails if** `INDEX.md` exceeds that strictest limit"* (`SOURCE_OF_TRUTH.md:259-261`). Nothing says which document wins. Severity high. Fix: B4.1's reference becomes the entries' own frontmatter `status` (`SOURCE_OF_TRUTH.md:105` — `INDEX.md` is *"generated, one line per active entry; never edited by hand"*), with `INDEX.md` named as a derived view; and B1.1's trigger stops depending on `INDEX.md` exceeding its limit.

**H4 — B1.2 — "an entry" weakens the settled vision, and no requirement anywhere sets a minimum n while the document says n=6 is too small to act on.** Vision: *"Vector search, run on the recorded misses, finds entries full-text did not, and does no worse on the other questions (B1.2)."* Requirement: `CACHES.md:376-377` *"the vector index finds **an entry** that full-text missed"*, and `:390-391` *"**Fails if** a vector index exists … with no recorded comparison in which it found **at least one** missed entry"*. One lucky hit out of one recorded miss passes the whole trigger. Against the document's own precedent: `:144` *"BM-5 (n=6, too small to act on)"*, `:302` *"n = 6 to 10 per category"*, and `:581-583` *"**B1.1:** no verdict at n=5."* Severity high. Fix: state the rule as a proportion or count over the recorded misses (and mark the number *proposed*), or restore the vision's wording and let EJ set the bar.

**H5 — B1.2 — the miss definition drops the one condition `V-F13` says makes it a *meaning* miss.** `CACHES.md:379-380`: *"**A miss** is a question where the entry existed, `INDEX.md`, grep and full-text search all missed it, and the agent found it another way (V-F13)."* `V-F13` says: *"the sort of queries that would justify a vector index are ones where the entry exists, the asker's words share no term with it, and grep, FTS and `INDEX.md` titles all miss"* (`vector.claude.md:165-167`). Without "shares no term", a miss caused by a stemmer, a typo, an entry that was never indexed, or an answer found in `journal/` or a run record counts as evidence for vectors. Severity high — it inflates the case for the cache in the direction the whole design is trying to be conservative about. Fix: restore the no-shared-term clause, or state the alternative (miss whose route failures are all lexical) as the discriminator.

**M1 — K3.1 — "a query's cost" has no unit, and it lost R8.2's.** `CACHES.md:440-441`: *"A built cache keeps passing its own trigger: its B1 comparison is rerun on the recorded questions (Rd4), and a query's cost includes any rebuild it triggered (K2)"*. The replaced text was concrete: *"A rebuild costs less than the cache saves between rebuilds: its time is compared with the reading time the cache saved"* (diff, deleted R8.2). B1.1's measure is characters; a rebuild costs seconds and produces no characters — so the clause adds nothing measurable, and it bundles a rerun rule with a cost rule (two events). The example table that used to justify R8.2 — `CACHES.md:568-579` *"### K3: rebuild cost … 0.169 s for 490 files … So K3 starts to bite with corpus size"* — now supports a requirement that never counts time. Severity medium. Fix: either restore "rebuild seconds vs reading seconds saved on the recorded questions", or say what unit "cost" is and delete the rebuild-seconds table from K3's evidence.

**M2 — B1.2 "Loses nothing" compares means taken over different question sets.** `CACHES.md:382-383`: *"the characters read to the first right entry are no more than full-text's"*. The source measurement is per-route: *"the mean number of characters … over the answers that named one; `n` is how many did. A miss is left out"* (`results.md:28`) — vector 923 chars over 19 questions against full-text 451 over 25 (`:99-100`). Severity medium. Fix: compare on the intersection of questions both routes answered, and state that.

**M3 — B1 / B1.0 / K3.3 — two `Fails if` clauses depend on "a decision by EJ" that nothing requires to be recorded.** `CACHES.md:392-393` *"**Fails if** a cache exists under `project-memory/.cache/` with no recorded comparison showing its trigger fired, or with no decision by EJ to build it"*; same clause at `:391` and `:446`. The comparison is a file; the decision is not. `Rd4.4` (`:486-488`) lists six fields and none is a decision, so the check can only be run by asking EJ. Severity medium. Fix: add the decision to the record (who, date, build / do not build) so the check is repo-verifiable, or mark both clauses "(judged)" as `SOURCE_OF_TRUTH.md` does elsewhere.

**M4 — B1.1 has no `Fails if` of its own, though the section promises one each.** `CACHES.md:354-355`: *"Each has a check, **Fails if**, that some case breaks."* B1.2 carries one (`:390`), B1 carries one (`:392`), B1.1 has none — and B1's own clause cannot catch a B1.1 comparison that ran on two easy questions and passed. Severity medium. Fix: give B1.1 the same shape as B1.2's clause.

**M5 — B2.2's check fails for reasons outside the cache.** `CACHES.md:401`: *"The cache directory is ignored by git and a rebuild leaves `git status --short` clean."* In this repo the tree is routinely dirty, so a concurrent edit fails the check; and "ignored by git" is already implied by "clean". Severity medium (one thing / checkable). Fix: `git status --short` before and after, or `git check-ignore -q project-memory/.cache/`, one per half.

**M6 — K1.1 cites `S-F9` for the opposite of what `S-F9` says.** `CACHES.md:424-426`: *"The index records a content hash … A newest-mtime check is not enough: a deletion leaves no newer file (K2.1). (S-F9)"*. `S-F9` is the mtime tool: *"`query` compares the index build time with the newest source mtime and rebuilds first if the index is stale"* (`sqlite-fts.claude.md:80`). Hashing is `S-F11` (SHA-256 per file) and `S-F12`; the node lists the staleness test as still undecided: *"staleness test (mtime as in F9, or hash as in F11)"* (`sqlite-fts.claude.md:138`). Severity medium. Fix: cite S-F11/S-F12 for the hash and mark "mtime is not enough" as the author's reading; or say the design has chosen hash over mtime and why.

**M7 — Rd4's record cannot be counted by the requirements that read it.** `CACHES.md:486-488`: *"whether it was a miss, and if so **how the entry was found**"* — free text, no category — while B1.2 needs the set of misses and K3 needs the set of questions. Nothing in `Rd4.4` says who curates the set, and `:489` admits the record's home is not in the sibling design: *"**Not yet done:** `SOURCE_OF_TRUTH.md` § Where it is put does not list `questions/`; adding it waits for EJ."* Severity medium. Fix: make "how found" a fixed vocabulary (journal, a run record, `covers:` link, asked EJ, code), and treat `questions/` as proposed in both documents or neither.

**M8 — three different corpora, and nothing says which files are indexed.** Vision: *"two optional indexes over the project's markdown memory"*; `B2` `:396`: *"computed from the memory's markdown"*; `B4.1` `:411`: *"the same set of entries as `INDEX.md`*. `Rd4.3` then creates `project-memory/questions/` inside that tree, committed, one file per session, with nothing excluding it from the index. Severity medium (gap-adjacent; see Gaps). Fix: one sentence in B4 — the index covers `entries/`, files whose frontmatter `status` is `active` — plus an explicit exclusion of `questions/`, `journal/`, `work/`.

**M9 — nothing requires the vector rebuild to happen in the same step as the full-text one, which is the failure `V-F24` names.** The vector 5W1H says it (`:247` *"Rebuilt with the full-text index, in the same step, so the two cannot disagree (`V-F24`, my reading)"*) but no requirement says it; `V-F24` is exactly about the alternative: qmd's `embed` *"is a second step, so between the two steps changed files have no current vectors"*, and Basic Memory's *"does not discover new files on disk … two rebuild paths that can disagree if one is skipped"* (`vector.claude.md:263-266`). `K2.1` checks each index's own hash, so a rebuild of one and not the other passes. Severity medium. Fix: a K2 sub-clause — the vector index is rebuilt by the same command and the same step, or is marked stale when the full-text one rebuilds.

**M10 — B5.1's vector half has no observation method.** `CACHES.md:417-419`: *"The documented rebuild completes without a model call, except the embedding step of B1.2. *Example:* rebuild with no model credentials available; the full-text path still works."* The negative test works for the full-text arm and cannot work for the vector arm (its allowed call is the one that needs the model); and *"the vector rebuild calls any model but its embedding model"* needs a way to see every outbound call, which is not stated. Severity medium. Fix: name the observation — rebuild with network egress blocked and the embedding model loaded locally, and inspect the process — or move the vector half to "the vector rebuild makes no call other than the embedding model, named in the record".

**M11 — `Rd1`'s attribution.** `CACHES.md:453` cites M18 for *"never read at session start"*. **M12 — "Rules for all three caches" is the cited `(d)` source of B4, K1 and K2, but the scope is now two caches.** `:160` *"## Rules for all three caches"*; `:154` *"**Unchanged:** the rules for all three caches below"*; `:9-10` says the graph *"was taken out of the requirements"*. Severity low-medium (leftover text inside the sections the requirements point at). Fix: "for every cache" throughout.

**M13 — `S-F13` cited for "nothing is measured", where `S-F13` measures exactly those sizes.** `:370-371` *"(S-F5, S-F13: nothing is measured yet for a corpus of a few hundred to a few thousand short entries)"*. `S-F13` ran 100 / 1,000 / 10,000 / 50,000 synthetic entries *"shaped like the design"* (`sqlite-fts.claude.md:98-107`); what it does not measure is tokens: *"Token cost to the agent is the real axis and this test does not measure it."* `S-F5` alone supports the clause. ## Gaps

- **No requirement creates the tool.** B2.1, B3.1 and B5.1 all check *"the documented rebuild"* and K2.1/Rd3 assume *"the tool"*, but nothing requires that a rebuild command, a query command, or any documentation of them exist — the vector 5W1H's *"through the same command as full-text search"* (`:245`) is design text only. Without this, four `Fails if` clauses presuppose an artifact no requirement produces.
- **No requirement states the result shape that justifies building FTS at all.** The only stated reason is *"ranked results with snippets save opened files"* (`:71`); `Rd2.1` requires only that the entry path is named. Ranking and the snippet are what B1.1's `chars` comparison depends on — the benchmark's `chars` column *"measures the print format as much as the store"* (`results.md:28`) — and nothing pins them. The `S-F16` trap (a plausible tokenizer change returning zero rows silently) likewise has no requirement; the default `unicode61` choice lives only in the 5W1H (`:208`).
- **No requirement fixes the corpus boundary.** `entries/` only? every active entry by frontmatter `status`? explicitly not `questions/`, `journal/`, `work/`, `.cache/`? Three documents currently say three different things (see M8).
- **No requirement says where EJ's decision is recorded**, so B1.0, K3.3 and two `Fails if` clauses are unverifiable from the repo (see M3).
- **No requirement covers two agents on one cache file.** `SOURCE_OF_TRUTH.md:198-200` puts each agent on its own branch or worktree, so two agents can run the same rebuild against `project-memory/.cache/index.sqlite` and rename over each other; the atomic-rename rule (K2.1) covers a reader mid-publish, not two publishers.
- **No requirement says a recorded miss is re-testable.** B1.2 reruns "on the recorded misses", which are facts about a corpus at a date; nothing records which revision of `entries/` the rerun used, so a pass cannot be attributed to the misses it was claimed to fix.
- **No owner and no bound for `questions/`.** One file per session, committed, for the life of the project, with no pruning rule and no statement of who reads it besides the comparison.
