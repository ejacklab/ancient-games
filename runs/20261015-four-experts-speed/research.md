# Findings — four-experts panel speed, cost, personas and calibration
Produced 2026-10-15 by researcher (Claude Opus 5.5, subagent). Question asked: "We run a 'panel of experts' setup: one question goes to 5 different LLM engines (Codex/GPT, Gemini via a CLI, DeepSeek, MiniMax via opencode, Claude), each with a persona built from an 18–20 item numbered list of decision rules (~40–55 KB list + ~16–23 KB identity file, so ~20k tokens of persona context read every call). Each must write a fixed 5-section answer (5–15 KB). They run in parallel; the slowest one gates the result; then an orchestrator reads all 5 answers and writes a comparison. Measured: 1.5–5.5 min per round even for tiny yes/no 'approve this' questions; Codex burns 32k–79k tokens per answer; agents also wander (run git log, ls, rg, re-read files) with no tool budget. A sequential 'relay' variant (each expert improves one shared copy) took 15–19 min. Find evidence-backed answers to: 1. What drives latency/cost in multi-agent debate / LLM-ensemble / panel setups, and when does adding agents stop paying? 2. Proven ways to cut latency for such panels [early-stop, cascades/routing, expert subsets, prompt caching, persona compression, output caps, tool budgets, first-to-finish, sparse topologies]. 3. Does persona prompting actually improve answer quality? 4. LLM calibration / expressed uncertainty [why models hedge, verbalized confidence calibration, techniques to state confidence clearly and correctly]." Source window: 2023–2026.

**How to read the labels here.** For papers I read the arXiv abstract page (and, for one paper, the HTML body), not the
results tables. A claim row about a paper's result is therefore `reported`: the abstract is the authors' account, and
the paper's tables, which hold the evidence, were not inspected. Vendor documentation is `verified` only for what the
vendor documents about its own product (prices, cache rules); a vendor's performance rule of thumb with no data shown
is `unproven`. The "Kind" the brief asked for (measured result vs opinion) is written at the end of each Finding. All
quotes were returned by the fetch tool's reading of the page; see Gaps.

## 2. Ways to cut latency and cost

| id | Finding | Label | Source |
|---|---|---|---|
| F18 | Adaptive stopping (stop sampling when the answers agree enough) cut sample budget up to 7.9x with under 0.1% average accuracy loss. Kind: measured. | reported | Aggarwal, Madaan, Yang, Mausam, "Let's Sample Step by Step: Adaptive-Consistency for Efficient Reasoning and Coding with LLMs", https://arxiv.org/abs/2305.11860 (v1 2023-05-19), quoted: "reduces sample budget by up to 7.9 times with an average accuracy drop of less than 0.1%" |

| F20 | Weighting each vote by the model's own confidence cut the reasoning paths needed by over 40% on average. ## Where sources disagree (kept apart, not averaged)

- **More agents help (F7) vs non-monotone (F9).** F7 reports steady gains up to 40 sampled agents on its tasks; F9
  shows voting accuracy can rise then fall when a task mixes easy and hard queries. Unresolved by me; both rest on
  abstracts.
- **Debate helps (F16) vs voting explains it (F10, F11, F12).** The later papers find most of debate's gain comes from
  voting/ensembling, or that a strong single prompt nearly matches it.
- **Mixed models help (F15) vs hurt (F14).** ReConcile (2023 models, confidence-weighted) reports gains from diverse
  LLMs; Self-MoA (2025) reports mixing usually lowers average quality.
- **Personas help (F35) vs do not (F33, F34).** The positive result is on 2023 ChatGPT reasoning benchmarks; the
  negative ones are on factual QA, with F34 on six newer models.

## Inference (my reading, not findings)

These are deductions for the four-experts setup; none was measured on it.

- From F1, F30: the 5–15 KB fixed answer is the likely main latency term per engine, more than the ~20k-token persona
  input (F1 says input length moves latency 1–5%). Caching the persona (F25, F27) mainly cuts input cost and
  time-to-first-token, not generation time.
- From F5, F31, F6: the gate is the slowest engine; an unbudgeted agentic CLI that runs git/ls/rg adds round trips
  (F2 "Make fewer requests") and F31 suggests a budget shown to the agent does better than a bigger budget.
- From F11, F12, F18–F21: for a yes/no approve question, a vote with early stop (stop when k agree) is the
  evidence-backed shape; a full five-section essay from five engines has no measured support as the better choice.
- From F28, F17: a 20-item, 40–55 KB rule list is in the range where long input and many simultaneous instructions are
  reported to cost accuracy; F29 is evidence that compression can be cheap, but no source tested short vs long
  *persona rule lists* specifically.
- From F33–F35: personas are unlikely to improve factual accuracy; whether a decision-rule persona (a method, not a
  job title) behaves like these "expert" labels is not tested by any source read.
- From F37–F43: hedging and unclear confidence are a trained behaviour; the supported fixes are an explicit confidence
  field, permission to say "not verified", and verify-each-claim-against-a-quote before stating it.

## Gaps

- **Results tables not inspected.** For every arXiv paper I read the abstract page only (for 2402.05120 also the HTML
  body, via the fetch tool's summary). Hence `reported`, not `verified`. Benchmarks, models and effect sizes beyond the
  abstract were not checked.
- **Quotes passed through the fetch tool.** WebFetch returns a small model's reading of the page. Quotes were requested
  verbatim, but F36's wording is plainly the tool's paraphrase, and any quote may carry small errors. Re-check a quote
  against the page before relying on it.
- **No direct evidence on short vs long persona/rule lists.** No source found that compares a short decision-rule
  persona with a long one; F28 (instruction count) and F17 (input length) are the nearest. Queries run: none beyond
  the IFScale search — out of budget for this pass.
- **No measured study of first-to-finish / streaming / "first k agree" across *heterogeneous engines* in parallel.**
  F18–F21 are same-model sampling or same-family judges. Not searched separately.
- **No source on agentic CLI tool wandering** (Codex/Gemini CLI/opencode running git, ls, rg) beyond F6 and F31.
  Not searched.
- **Vendor docs undated.** F1, F2, F25–F27, F43 pages show no date; recorded as "undated; read 2026-10-15".
- **Not found:** an initial query for the Wharton persona report ("Wharton 'Playing Pretend' expert personas don't
  improve factual accuracy 2025", general web search) returned nothing relevant; a second query found it (F34).
- **Not read:** MACI (arXiv 2510.04488) and "Budgeted Act-or-Defer Multi-Agent LLM Deliberation" (alphaxiv 2606.29654)
  appeared in search results only; not fetched, no rows.
- **Budget used:** 6 web searches and 38 page fetches (including one redirect re-fetch). No budget was given in the
  brief; stopped when each of the four questions had sourced rows or a named gap.
